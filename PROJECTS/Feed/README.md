# Feed

Страница кнопки «+», показывающая **всё**, что сервер записал по одной сессии: не пересказ ленты чата, а её полный разбор — каждый шаг раскрывающейся карточкой со всеми полями, которые отдаёт `/api/sessions/messages`.

Папка — это и есть страница целиком (`DOCS/decisions/016`): в `SYSTEM/index.html` про неё нет ни строчки.

| Файл | Что в нём |
|---|---|
| `page.js` | страница целиком: `export default build(page, { panel, signal })`, панель выбора сессии в топбаре, лента карточками |
| `page.css` | её стили; `<link>` ставит загрузчик по имени папки, поэтому правка подменяется на лету |
| `README.md` | этот файл — карточка раздела во вкладке Book |

## Что на экране

- **Панель в топбаре** — выпадающий список сессий и кнопка «⧉» (скопировать id выбранной). Слот под неё выдаёт `SYSTEM/new-button.js`, он же показывает и прячет его вместе со страницей — `page.js` только наполняет. Вид одолжен у панели зума Flow (`.flow-canvas__zoom`), своих правил на неё в `page.css` нет: пока это так, панель зависит от `PROJECTS/Flow/flow.css`.
- **Первая карточка** — сводка по самой сессии: `contextPercent`, `sessionInfo`, `rateLimit`, суммарные токены/кэш/стоимость/длительность.
- **Дальше** — по карточке на шаг: текст, `toolInput`/`toolResult` целиком, модель и effort, токены хода, `stopReason`, `tool_use_id`/`parent_tool_use_id`. Раскрыта не больше одной сразу; открытие новой закрывает предыдущую. По умолчанию лента проматывается вниз, к последнему шагу.

Выбранная сессия запоминается в `localStorage` (`sessionFeed.lastSessionId`), поэтому страница открывается там же, где её закрыли.

## Почему поля рисуются от данных

Строка появляется только там, где сервер значение действительно прислал, а всё, что он прислал сверх известных полей, показывается сырым именем ключа (`fillKv` в `page.js`). Раньше было наоборот: пустые поля занимали место прочерком «—», а новое поле протокола CLI пропадало молча, потому что его не было в зашитом списке. Это прямое продолжение `DOCS/decisions/012` — из стрима CLI не теряем ничего.

## Живая лента

Пока по выбранной сессии идёт ход, страница подписана на её поток (`/api/sessions/attach`, тот же приём, что во Flow) и дочитывает `/api/sessions/messages`, дорисовывая карточки по мере появления. Ход мог начаться и не отсюда (например, из вкладки Chat) — тогда страницу будит событие `session-running-changed` на `body`, которое шлёт `SYSTEM/app.js`.

## Пересборка на лету

Правка `page.js` пересобирает эту страницу и только её: остальной интерфейс — открытая сессия, набранное сообщение — остаётся на месте (`DOCS/decisions/016`). Держится это на том, что модуль ничего не делает за пределами выданного: рисует в `page` и `panel`, а слушателя `session-running-changed` на `body` и поток `/api/sessions/attach` вешает на `signal`. Добавляя сюда что-то новое, подписывайте тем же сигналом — иначе от прошлой сборки останется живой хвост.

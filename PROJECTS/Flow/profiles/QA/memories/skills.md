## Проверять живой интерфейс, а не только разбор файла

- **Когда применим:** Правка клиентского файла вкладки завершена, node --check прошёл
- **Что делать:** node --check видит только синтаксис. Обращение к необъявленному имени ловит npm run check (правило no-undef), а упавший обработчик и пустую панель — только живой прогон вкладки на сервере, поднятом пользователем (DOCS/decisions/002).
- **Чем подтверждён:** В flow.js жило обращение к ненаписанной ROOT_FIELDS: node --check проходил, панели карточек упали бы у обеих ролей сразу
- **Записано:** 2026-09-07 (сессия 1a3d5d21)

## Живая проверка хуков Claude Code короткой новой сессией

- **Когда применим:** Правил .claude/settings.json (регистрация хуков, enabledPlugins) или скрипт в .claude/hooks/: текущая сессия держит снимок хуков со старта и новую регистрацию не видит
- **Что делать:** Из корня проекта: claude -p "<просьба выполнить ровно одну запретную команду и не обходить отказ>" --output-format stream-json --verbose --max-turns 4 --model haiku > файл.jsonl; в событии init смотреть число skills/agents/plugins, в tool_result — текст отказа «PreToolUse:Bash hook error: …». Запретную команду брать такую, чей проскок обратим (git add -A при чистой рабочей копии, bd close эпика — есть bd reopen), и после прогона сверять git status и bd show. На одну сессию — одна команда: после первого отказа модель останавливается
- **Чем подтверждён:** 2026-09-20: так подтверждены commit-guard.js (отказ в git add -A, индекс пуст), epic-close-guard.js (отказ со списком детей), снятие clarify-vague-request и выключение плагинов для проекта (34 скилла вместо 397)
- **Записано:** 2026-09-20 (сессия OpenKarandash-a1u)

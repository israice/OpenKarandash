# Домашняя работа

Один вызов собирает то, что иначе модель ищет сама: файлы с диапазонами строк,
текущие значения, правила типа задачи и команду проверки.

```bash
node TOOLS/homework/run.mjs "текст задачи"
node TOOLS/homework/run.mjs --file brief.txt --out report.md --quiet
```

Текст задачи передаётся вместе со строкой `UI element: «New» button#newButton…`,
если человек кликнул по элементу в интерфейсе: она даёт точные якоря (классы и
id), и отчёт выходит точным. Без неё сбор идёт по словам комментария.

Код выхода: 0 — отчёт собран, 1 — нечего искать, 2 — неверный вызов.

## Что в отчёте

Файлы с номерами строк и окнами вокруг попаданий, поиск по индексу проекта,
указание на файл правил по типу задачи, команда живой проверки. Правила в
отчёте — указанием на файл, а не текстом: агент прочитает его с диска, когда
понадобится, а отчёт останется маленьким.

## Когда отчёт пустой

Это не поломка, а факт: место описано словами, а в коде оно называется иначе
(«первой открывается Home» — это `defaultView` и `lastView`). Отчёт прямо
говорит об этом и предлагает два выхода: спросить человека, какой элемент
трогать, или сделать один `node PROJECTS/Graph/search.js "2-4 слова"`.

Слой смыслового разбора, который закрыл бы такой случай автоматически, не
написан намеренно: на трёх задачах из четырёх сборщик справляется сам
(`DOCS/decisions/084`).

## Чего он не делает

Не поднимает сервер и не проверяет живую страницу — этим занимается
`TOOLS/live-verify/`, см. его `README.md`. Не правящий код и не принимающий
решений: только разведка.

## Файлы

| Файл | Чем занят |
| --- | --- |
| `anchors.js` | Якоря из текста задачи: классы и id из `UI element`, camelCase и заглавные слова из комментария, тип задачи по шести категориям |
| `collect.js` | Исполнение плана: `rg` по якорям с ранжированием по специфичности, окна вокруг попаданий, поиск по индексу |
| `run.mjs` | Запуск из командной строки, разбор аргументов, коды выхода |

Проверки: `npm run check`. Живая проверка — сервер поднимает владелец
(`DOCS/decisions/002`).

# Содержимое сессии

```bash
node TOOLS/sessions/read.mjs kilocode-local-muuqh9z5
node TOOLS/sessions/read.mjs kilocode-local-muuqh9z5 --last 2
node TOOLS/sessions/read.mjs "второе выпадающее меню"
```

Сессия называется тремя способами, все перебираются по точности: полный id,
уникальный префикс id, часть заголовка. Последний покрывает «название сессии»
дословно — в панели название это и есть заголовок, то есть первая реплика
человека.

На выходе заголовок, время, число ходов, потраченные токены и деньги, **id внутри
CLI** (продолжить сессию можно только им, `SYSTEM/core/handoff.js`), а затем сами
ходы: реплика человека, ответ, шаги инструментов одной строкой каждый. Мысли
(`role = 'thinking')` текстом не печатаются — в ответе указано их количество.

`--last N` оставляет последние N ходов: длинная сессия целиком не читается, а
для most-задачи хватает хвоста.

Если сессия не найдена, печатаются восемь последних с заметками — искать не
приходится, выбор делается сразу.

Код выхода: 0 — нашлась; 1 — не нашлась; 2 — неверный вызов.

## Откуда он берётся в интерфейсе

Кнопка копирования в строке сессии кладёт в буфер не голый id, а адрес:

```
Сессия OpenKarandash: kilocode-local-muuqh9z5
— «UI element: span.provider__model-label …»
Прочитать целиком: node TOOLS/sessions/read.mjs kilocode-local-muuqh9z5
```

Так сделано потому, что id сессии вне интерфейса не открывается: получатель
начинает искать, где такие сессии лежат (`DOCS/decisions/099`).

## Чего он не делает

Только чтение `DATA/.sessions.db`, как `TOOLS/steps` и `TOOLS/suggestions`;
`SESSIONS_DB` задаёт другую базу. Он не продолжает сессию и не запускает ход —
для этого есть `--resume` с id внутри CLI из шапки отчёта.

Проверки: `npm run check`. Живая проверка здесь не нужна — скрипт работает с
базой, а не со страницей.

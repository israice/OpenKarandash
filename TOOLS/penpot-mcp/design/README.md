# Дизайн CLI-дропдауна в Penpot

Макет выпадающего меню выбора CLI в шапке сессии: закрытое и раскрытое
состояния, состояния пунктов, правила поведения, палитра. Рисуется не руками в
интерфейсе, а кодом через MCP Penpot — фигуры создаёт плагин в браузере по
`tools/call execute_code`.

Что заменяем: сейчас уровень CLI в шапке — нативный `<select>` с 51 пунктом
(`SYSTEM/model-cascade.js`, `modelCascadeRow()`), без иконок, без поиска, без
групп; в раскрытом виде фон невыбранного пункта темнее выбранного
(`SYSTEM/styles/model-cascade.css`).

## Запуск

Нужен поднятый стек (`docker-compose -f deploy/penpot/docker-compose.yaml up -d`)
и браузер с подключённым плагином:

```bash
node TOOLS/penpot-mcp/connect.mjs
node TOOLS/penpot-mcp/design/build.mjs --check --preview
```

`--check` прогоняет линтер вёрстки и роняет сборку при проблемах, `--preview`
кладёт `preview.png` рядом. Одно и то же, но через скриншот, ловится хуже и
медленнее, поэтому линтер — основная проверка, скриншот — для глаза.

Скриншот с зумом на фигуру:

```bash
node TOOLS/penpot-mcp/design/shot.mjs out.png "Menu"
```

Новый экран начинается с заготовки, а не с пустой доски:

```bash
node TOOLS/penpot-mcp/design/scaffold.mjs "Модели" --x 3300
```

Заготовка сразу проверяется линтером и зумит канвас на новую доску.

## Устройство

| Файл | Что делает |
| --- | --- |
| `theme.json` | Единственный источник цвета, типографики, радиусов, отступов и цветов агентов. Правь тему здесь |
| `mcp-client.mjs` | Клиент MCP: `initialize` → `notifications/initialized` → `tools/call` |
| `helpers.js` | `box`/`text`/`icon`/`logo`, роли типографики `T()`, радиусы `R()`. Подставляется в начало каждого шага |
| `lint.js` | Проверка вёрстки: переполнение текста, выход за родителя и за доску, наезд сиблингов, текст без заливки и текст цвета фона, координаты не кратные 4 |
| `lint-selftest.mjs` | Проверка самого линтера на заведомо сломанной геометрии — без неё непонятно, работает ли он вообще |
| `tokens.js` | Локальная библиотека цветов, набор токенов `cli-dropdown`, доска `CLI dropdown` |
| `components.js` | Доска `Kit` и компоненты |
| `header.js` | Заголовок макета и закрытое состояние |
| `panel.js` | Раскрытое состояние меню |
| `states.js` | Правая колонка: состояния, правила, палитра |
| `apply-tokens.js` | Применяет токены к живым фигурам; падает, если фигура или токен не нашлись |
| `build.mjs` | Прогоняет шаги, идемпотентно |
| `shot.mjs` | Скриншот канваса из браузера |
| `scaffold.mjs` | Заготовка экрана: шапка, две колонки, линтер, зум |

Всё идемпотентно: доска и токены создаются, если их ещё нет, содержимое
пересобирается заново, поэтому шаги можно гонять много раз.

## Компоненты

`Menu item` — четыре варианта по оси `State` (`Default` / `Hover` /
`Selected` / `Disabled`), `Select pill` — два (`Idle` / `Active`), плюс
`Search field`, `Section label`, `Kbd hint`, `Card`, `Divider`,
`Menu item add`, `Empty state`.

Пункты меню, полоса-разделитель и заглушка `Add` на макете — инстансы, а не
нарисованные фигуры:

```js
const inst = itemComponent.instance();
menu.appendChild(inst);
penpotUtils.setParentXY(inst, 12, y);
inst.switchVariant(0, a.state);            // состояние, а не отдельная вёрстка
```

Меняются только переопределения — подписи и цвет плитки. Переопределения на
инстансе работают: `characters`, `fills`, `fillColorGradient` применяются без
`detach()`, структура (радиус, акцентная черта, галочка) остаётся от
компонента. Новый экран — это раскладка инстансов, а не рисование с нуля.

## Палитра и токены

`theme.json` — источник правды: цвета, роли типографики (`eyebrow`, `title`,
`itemName`, `body`…), радиусы, отступы, цвета плиток агентов. `helpers.js`
собирает из неё палитру (`storage.design.C`) и роли `T('itemName')` / `R('item')`,
поэтому значения не дублируются по шагам и правка темы не требует обхода
файлов.

`tokens.js` переносит палитру в локальную библиотеку Penpot и 20 токенов
набора `cli-dropdown` (`color.*`, `space.*`, `radius.*`). `apply-tokens.js`
применяет их к живым фигурам и падает, если фигура или токен не нашлись: молча
пропущенный токен — это разъехавшаяся тема.

## С каким агентом это работает

Пайплайн не привязан к конкретному CLI. Всё, что он делает, — обычные скрипты
Node без единой зависимости: `mcp-client.mjs` использует только глобальные
`fetch` и `WebSocket`, то есть нужен Node 22+ и ничего больше. Достаточно, чтобы
агент умел выполнять команды в папке проекта:

```bash
node TOOLS/penpot-mcp/connect.mjs
node TOOLS/penpot-mcp/design/build.mjs --check
```

Свои MCP-инструменты агенту для этого не нужны: `mcp-client.mjs` говорит с
сервером по протоколу напрямую. А если агент MCP поддерживает, Penpot
подключается в его собственном конфиге, и `execute_code` зовётся как обычный
инструмент:

| Конфиг | Кто читает |
| --- | --- |
| `.mcp.json` | Claude Code и другие клиенты стандарта MCP |
| `kilo.json` | Kilo |
| `opencode.json` | OpenCode |

Агентам без поддержки MCP или без своего формата конфига это не блокер, а повод
не добавлять запись: пайплайн работает через `mcp-client.mjs`.

Что всё же различается между агентами:

- **Права на запуск команд.** Агент, спрашивающий подтверждение перед каждой
  командой, превратит одну сборку в десяток диалогов. `build.mjs` идемпотентен
  и безопасен для повторов.
- **Умение смотреть картинки.** `shot.mjs` и `preview.png` бесполезны агенту,
  который не читает изображения. Основная проверка — `--check`, работает всегда.
- **Объём контекста.** Шаги и `helpers.js` занимают прилично места; агенту с
  коротким контекстом проще править существующий файл-шаг, чем заводить новый.
- **Память между вызовами.** `storage` в плагине Penpot живёт дольше сессии
  агента, поэтому палитра в `helpers.js` дополняет недостающие ключи, а не
  читается как есть.

## Что показала практика API

- `Path` не умеет `fromSVG` — иконки собираются через `penpot.createShapeFromSvg`,
  он возвращает группу с обводкой, цвет зашивается в строку SVG.
- Контейнером может быть только `board` или `group`: `appendChild` в
  прямоугольник падает с «Value not valid: :rect».
- `penpot.createText()` без аргумента не создаётся, `layoutChild` только
  читается, `resize(0, …)` не принимается, у flex-контейнера зазв — это
  `columnGap`/`rowGap`, а не `gap`.
- В flex-колонках размер считается по содержимому, поэтому колонки с
  авто-размером наезжают друг на друга — задавать стартовую ширину руками.
- `createVariantContainer` кладёт контейнер в мировые координаты и в родительскую
  доску не возвращает: после вызова нужен `appendChild` в нужную доску и
  `setParentXY`.
- `createComponent` не берёт фигуры, уже лежащие внутри variant-контейнера:
  сначала компонент на каждый экземпляр, потом группировка в варианты.
- `storage` в плагине переживает вызовы `execute_code`, поэтому палитра
  дополняется недостающими ключами, а не читается как есть — иначе шаг,
  написанный раньше, отработает с неполной палитрой молча и уедет цветом.
- **Размеры текста асинхронные.** Сразу после `createText` у текста `width` и
  `height` равны 1 px; настоящие значения появляются только после `await` на
  самом тексте. `await` на доске или на корне не помогает. Из этого следует
  и линтер, и `logo()`: буква центрировалась по ширине 1 px.
- **`opacity` может быть не задан**, поэтому `undefined > 0` отсекал всё
  дерево обхода — линтер молчал, ничего не находя. Проверка видимости должна
  быть `(s.opacity ?? 1) > 0`.
- `export_shape` рисует без шрифтов (см. выше).

## Как это переносится в код

Правила и состояния расписаны на самой доске: поиск с `/`, две группы
(подключённые → каталог), вторичные подписи (шлюг и число моделей либо «нет
коннектора»), `Add` остаётся последним и остаётся заглушкой — виден, но не
выбирается. Пункт `Add` в коде заведён как `ADD_OPTION` с `disabled = true`
(`model-cascade.js`), поэтому и в макете он приглушённый и пунктирный.

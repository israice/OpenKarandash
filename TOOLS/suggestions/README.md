# Что подкладывалось в запросы

```bash
node TOOLS/suggestions/run.mjs            # сводка с последнего вызова
node TOOLS/suggestions/run.mjs 50         # последние 50 ходов с подробностями
```

`run.mjs` читает `DATA/.sessions.db` и достаёт из `result_meta` каждого хода поле
`suggestions`: какие записки `DOCS/decisions`, какой приём из памяти работника и
какой отчёт разведки были подложены в запрос и с какими оценками. Он ничего не
пишет и никуда не ходит.

Поле `suggestions` лежит в строке **ответа** агента, а не в строке запроса: ход
дописывается в базу в конце, и оценки достаются оттуда. Раньше свода фильтровала
`role = 'user'` и потому показывала ноль при заполненной базе — сломанный отчёт
был виден только через прямой запрос к базе.

Базу можно подменить: `SESSIONS_DB=путь/к/копии.db node TOOLS/suggestions/run.mjs`.
Это для проверки на копии — живую базу не трогают, а разбор полей (`sent`,
`work`, `reused`) иначе нечем проверить, пока настоящих ходов с отчётом ещё нет.

## Что смотреть

**Сколько подсказок на ход** — если их почти нет, порог высокий; если почти на
каждом ходу, низкий. Средняя доля верных попаданий по каждому порогу показывает, где
его стоит двигать.

**Распределение оценок** — то, из чего порог и выводится: между верными
попаданиями и шумом должна быть видимая граница. Если её нет, порог ничего не
решает, и виноват не порог, а вопрос.

**Одна и та же записка много раз подряд** — верный признак, что её описание
надо переписать: подбор попадает в неё на несвязанные задачи.

**Отчёт разведки: «в запрос ушло»** — сколько символов реально занял отчёт
(`sent`), а не сколько он весил целиком (`chars`). У продолжающего хода едет
карта: она в десять раз короче отчёта, и без отдельного поля средний объём
смешивал бы две разные вещи в одну цифру. Колонка «карта вместо отчёта» считает
продолжения сессии — их рост означает, что память сессии работает.

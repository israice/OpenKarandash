# Laya в проекте

[Laya](https://github.com/NandhaKishorM/laya) — не генератор макетов, а движок
типизированных решений по тексту: `choice` / `score` / `noul` в одном
прямом проходе плюс `Router`, который выбирает чекпойнт под язык. К Penpot и
рисованию он отношения не имеет.

Ставится сюда не ради дизайна, а ради двух вещей, где выбор «одно слово из
списка» реально повторяется и где промах дорог:

- разбор пользовательских правок к макету — «какой элемент трогать», «какая
  часть жалобы про выбранного агента», без разбора текста глазами;
- маршрутизация задач (веб-правка макета → только Penpot, правка поведения →
  только код) — это `Router` с чекпойнтом по типу задачи.

Как генератор интерфейсов он бесполезен: ни Penpot, ни Figma, ни экспорта
макетов в нём нет. Ставится отдельно от `TOOLS/penpot-mcp/design` и не должен
смешиваться с ними.

## Установка

Окружение лежит внутри проекта, в git не попадает (см. `.gitignore`):

```powershell
powershell -ExecutionPolicy Bypass -File TOOLS/laya/setup.ps1
```

Скрипт создаёт `TOOLS/laya/.venv` (Python 3.13) и ставит `laya`. HF-кэш
чекпойнтов переносится в `TOOLS/laya/hf-cache`, чтобы не писать в профиль
пользователя.

## Проверка

```powershell
TOOLS/laya/.venv/Scripts/laya.exe "Мы берём OpenCode" --preset triage
```

Первый запуск с чекпойнтом качает его с Hugging Face — это ~400 МБ на
чекпойнт, дальше берётся из кэша. Маршрутизация без скачивания работает
сразу.

## Чего от него фактически польза (замеры)

Замеры сделаны на `decide.py` — маршрутизация запроса в `design` / `code` /
`content` / `assets` / `question`:

| Запрос | Ответ модели | conf. | Что должно быть |
| --- | --- | --- | --- |
| сделай пункт меню чуть выше | design | 0.30 | design |
| клик не переключает выбранного агента | question | 0.71 | code |
| замени иконку поиска | question | 0.36 | assets |
| напиши подпись Add | question | 0.31 | content |

То есть базовый чекпойнт на нашей домене не годится: маршрут угадывает через
раз, а `confident` не коррелирует с правильностью — «клик не переключает» даёт
0.71 и при этом уходит в `question`. Это ровно то, о чём пишет README Laya:
на typed-decisions базовая модель даёт 0.362, после fine-tuning — 0.766.

Отсюда решение: `decide.py` оставлен как заготовка, но пользоваться его
ответом без дообучения нельзя. Порог `LAYA_MIN_CONFIDENT` (по умолчанию 0.6)
срабатывает не по правилу — на этих данных он бесполезен, и поднимать его
нельзя, пока чекпойнт не обучен на наших решениях.

## Что нужно, чтобы он заработал

Собрать размеченный набор решений по проекту (запрос → куда попал) и
дообучить чекпойнт — в README Laya это даёт основной прирост точности.
Накопитель таких решений стоит завести рядом с `TOOLS/penpot-mcp/design`:
одна строка на запрос, метка `design|code|content|assets`.

Пока это не сделано, выбор маршрута делает агент сам — он видит код проекта и
может отличить правку макета от правки поведения точнее, чем модель без
контекста проекта.

## Карта проекта и память

Знания о проекте живут в Obsidian-vault внутри репозитория: папка `vault/` (не коммитится). Сервер создаёт и наполняет её при запуске и обновляет через 3 секунды после правок.

Что в ней лежит:
- `vault/Проект/` — заметка на каждый файл папки проекта (включая скрытые и игнорируемые git; не обходятся только `.git` и сам `vault/`), на его секции и функции, плюс `API/` с заметкой на каждый роут. Связи берутся из настоящих ссылок: литералы `/api/...`, `src`/`href`, `require`, вызовы функций.
- `vault/Сессии/` — память о прошлых сессиях: что просили, чем закончилось, какие файлы затронуты. Помеченные `stale: true` устарели — после них файлы уже менялись.

Правила:
- Ищи по проекту командой `node search.js "запрос"` — полнотекстовый поиск (FTS5/BM25) по коду, заметкам и прошлым сессиям, выдаёт узел, путь и фрагмент. Фильтр: `node search.js --kind session "запрос"`. Индекс собирает сервер; MCP-инструменты `obsidian_*` не используем — они требуют запущенного Obsidian и токена.
- `vault/Проект/` перезаписывается целиком при каждой пересборке. Свои заметки клади в корень vault — их никто не тронет, и они попадут и в граф, и в поиск.
- Граф смотрят во вкладке Graph веб-интерфейса, приложение Obsidian не открывается.

## Конвенции

- Проект принципиально без зависимостей: только встроенные модули Node (`node:sqlite`, `http`, `child_process`). Не создавать `package.json`, не предлагать npm-пакеты.
- Порт и любые секреты — только в `.env` (создаётся при первом запуске с `PORT=3001`, в git не попадает). Сервер поднимается строго на этом порту и соседние не подбирает: вторая копия на той же папке дерётся за `.sessions.db`/`.index.db` и перезаписывает `vault/`. Новую настройку заводить в `.env`, а не хардкодом и не отдельным файлом.
- Комментарии в коде — на русском.

## Клиентский код

`index.html` — только разметка и стили. Скрипты подключены с `defer` отдельными файлами:

| Файл | Что в нём | Что публикует |
|---|---|---|
| `app.js` | ядро: настройки и провайдеры, панель сессий, лента сообщений | `window.App` |
| `graph.js` | вкладка Graph | `window.MissionGraph` |
| `flow.js` | вкладка Flow | `window.MissionFlow` |
| `kanban.js` | вкладка Kanban | — |
| `button-edit.js` | кнопка Edit целиком: своя разметка + комментарии к элементам | — |
| `menu.js` | меню-шестерёнка | — |
| `tabs.js` | панель вкладок, `showView` | `window.MissionTabs` |
| `toolbar-reorder.js` | drag-and-drop кнопок `.toolbar` по долгому нажатию | — |
| `sessions-toggle.js` | кнопка Sessions в тулбаре Chat | — |
| `sessions-projects.js` | стрелки ←/→ панели Sessions: Tasks ⇄ PROJECTS | — |

Правила, чтобы одна поломка не гасила интерфейс целиком:
- Никогда не класть JS обратно в `<script>` внутри `index.html`. Новый кусок интерфейса — новый файл с `defer`: браузер выполняет их независимо, и исключение в одном не отменяет остальные.
- Чужое (`App.openModal`, `MissionTabs.show`, …) вызывать **внутри функций и обработчиков**, а не на верхнем уровне файла. Тогда порядок загрузки ни на что не влияет и циклические связи безопасны.
- `app.js` идёт первым: остальные файлы берут из `window.App` общее ядро.
- Всё, что сервер подставляет в HTML (`{{APP_VERSION}}`, `{{VERSION_LIST}}`), обязано проходить через `escapeHtml` в `server.js` — иначе `<` из сообщения коммита рвёт страницу.

# Правила проекта: Проверка изменений

Часть `AGENTS.override.md`, разложенного по темам: горячие правила и маршрут по типу задачи лежат в самом `AGENTS.override.md`, остальное — здесь. Читать, когда задача подходит к концу: чем и в каком порядке проверять.

## Проверка изменений

- **Меньше чтения, больше фокуса.** Поиск и запрет грести `DATA/` — в горячем файле и `карта-проекта.md`. Читай ровно тот файл или участок, который нашёл поиск, и не читай соседние «на всякий случай».
- Перед словами «готово» агент обязан прогнать `npm run check` (`SYSTEM/checks.js`) — отдельным шагом после всех правок перед коммитом (один раз, не дважды). Это три проверки: неизвестные имена (`eslint`, единственное правило `no-undef`), циклические связи (`madge --circular server.js`) и счёт файлов длиннее 400 строк (норма `DOCS/decisions/022`). Первые две валят команду, третья только перечисляет. Нужна она затем, что разбор синтаксиса видит один синтаксис и пропускает обращение к переменной, которой нигде нет: так в `PROJECTS/Settings/settings.js` жил вызов потерянной `pickInstall`, а в `PROJECTS/Flow/flow.js` — обращение к ненаписанной `ROOT_FIELDS`, и падало это уже в браузере у пользователя (`DOCS/decisions/034`). Новое имя, публикуемое вкладкой через `window`, дописывается в список `APP_GLOBALS` в `eslint.config.mjs`, иначе проверка примет его за опечатку. Смоука в проекте нет (`DOCS/decisions/025`): автоматических серверных прогонов больше не заводим. Работает ли фича на самом деле, смотрит пользователь на своём сервере; клиентскую часть при необходимости проверяет агент (ui-walk / live-verify). Живой интерфейс после правок клиента агент проходит сам одной командой `npm run ui` (`SYSTEM/ui-walk.mjs`, `DOCS/decisions/048`): все вкладки, страницы «+» и окно настроек, ошибки консоли и пустые панели, код выхода 1 при замечаниях — на сервере, который поднял пользователь, а не сам агент. Сценарий под задачу (нажать, отправить короткий ход, сверить сессию в трёх отображениях) — готовые сценарии в `TOOLS/live-verify/` (`node TOOLS/live-verify/run.mjs <сценарий> [ключ=значение]`, подробности в `TOOLS/live-verify/README.md`); пробный ход виден владельцу — сессия появляется в его списке, а ответ уходит ему в телеграм, поэтому ход один, короткий, бесплатной моделью, и за собой убрать (`short-turn cleanup=1`).
- Ветку исполнителя перед любым рецензентом проверяет `npm run gate -- <ветка>` (`SYSTEM/branch-gate.mjs`): машинная проверка на её рабочей копии, затем прогон её предпросмотра, если тронут клиент; упавшая ветка до рецензента не доходит. Список и уборка веток — `npm run branches` (`SYSTEM/branch-sweep.mjs`). С `--task "поручение"` шлюз добавляет подсказку jev, по делу ли дифф (`070`); ветку по ней не отклоняют. Порядок целиком — `DOCS/decisions/049`.
- Тем же шагом в конце задачи агент дописывает приём в память своего работника — `PROJECTS/Flow/profiles/<Роль>/memories/skills.md` (`POST /api/flow/profile/memory/add`, серверная половина — `PROJECTS/Flow/profiles-server.js`), а в начале похожего задания читает её. Запись только о проверенном: четыре поля — когда применим, что делать, чем подтверждён, когда записано. «Наверное, помогает» засоряет память быстрее, чем приносит пользы (`DOCS/decisions/035`).
- Не запускать `server.js` из сессии — ни в фоне через `&`, ни на переднем плане. Без `NO_RELOAD=1` поднимается сторож с дочерним процессом, а на Windows завершение сессии не шлёт им сигналов: оба остаются жить. Осиротевший сторож держит cwd проекта (папку нельзя переименовать), сутками крутит опрос файлов и дерётся за `DATA/.sessions.db` со следующей копией. Никакой хук это больше не блокирует (`DOCS/decisions/078`), поэтому запрет держится на правиле: фразу запуска сервера не писать даже внутри кавычек или сообщения коммита — такие строки кладут в файл.
- Сервер для себя пользователь запускает сам: `node server.js` в своём терминале (PowerShell или WSL), останов — `Ctrl+C`. Сторож на старте проверяет системные зависимости и ставит недостающие (`SYSTEM/core/host-deps.js`: git и python; `HOST_DEPS=0` в `.env` выключает), а агентский CLI не ставит: opencode находит и подключает сам сервер через `/api/agent/detect` и кнопку Connect в Settings. Docker и WSL из проекта убраны, как и прежний стек с claude и Hermes (`DOCS/decisions/077`), — упоминаний о них в правилах больше нет.
- Если зомби всё же завёлся, искать по рабочему каталогу, а не по имени процесса — в диспетчере задач он неотличим от прочих `node.exe`:

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Select-Object ProcessId, CommandLine
Stop-Process -Id <pid> -Force
```

# Правила по темам — читать по надобности

Правила проекта разложены по темам, чтобы в каждой сессии читался только короткий `AGENTS.override.md` (горячие правила и маршрут по типу задачи), а отсюда — только нужный файл. Файлы переписываются по мере устаревания: мёртвое (убранные CLI, снятые решения) и продублированное из горячего файла вычищается, а не хранится.

| Файл | О чём | Читать, когда |
|---|---|---|
| `карта-проекта.md` | где знания проекта, полнотекстовый поиск `PROJECTS/Graph/search.js`, чего не грести | задача про поиск по проекту, заметки vault, память прошлых сессий |
| `конвенции.md` | один агент на проект и его права, автокоммит и версии, три отображения — один источник, язык ответа и писем, поручения и ходы, порт и секреты | любая задача; особенно — новая роль или поле сессии, коммит, ответ по Telegram |
| `сервер.md` | `server.js` как тонкий диспетчер, серверные половины фич, сессии, подключения и коннекторы CLI, коды ответов | правка серверной половины, сессий, запуск хода |
| `проверка.md` | `npm run check`, живая проверка, сценарии, разбор «сервер не отвечает», ветка исполнителя | задача подходит к концу и непонятно, чем проверять |
| `клиент.md` | карта клиентских файлов, разметка и подключение скриптов, серверные фрагменты htmx | правка разметки, клиентского скрипта или фрагмента |
| `перезагрузка.md` | живая перезагрузка после правки файла, правила, чтобы одна поломка не гасила интерфейс целиком | вопрос «почему после правки всё перезагрузилось», риск поломки загрузки |
| `измерения.md` | как не тратить шаги и контекст: один точный запрос, чтение без нужды, короткий вывод проверки | конец задачи или разбор сессии |

Порядок обычно такой: `AGENTS.override.md` → файл из таблицы по типу задачи → `измерения.md` на сверку. Всё остальное (`DOCS/decisions/`, заметки `DATA/vault/Project/`) ищется поиском, а не чтением подряд.

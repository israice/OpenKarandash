# Правила проекта: Клиентский код

Часть `AGENTS.override.md`, разложенного по темам: горячие правила и маршрут по типу задачи лежат в самом `AGENTS.override.md`, остальное — здесь. Читать, когда правка разметки, клиентского скрипта, серверных фрагментов.

## Клиентский код

Клиент целиком лежит в `SYSTEM/`. `SYSTEM/index.html` — только разметка: стилей внутри страницы нет, они подключаются файлами (`SYSTEM/styles/*.css` — общие части страницы, `PROJECTS/<Фича>/*.css` — сами фичи), и порядок `<link>` повторяет прежний порядок правил, то есть значим для каскада. Страница отдаётся по адресу «/», поэтому пути в ней пишутся от корня проекта (`SYSTEM/app.js`, `PROJECTS/Graph/file-editor.js`), а не относительно самого файла. Скрипты подключены отдельными файлами: обычные — с `defer`, входы вкладок, разъехавшихся на ES-модули (`SYSTEM/app.js`, `PROJECTS/Sessions/sessions.js`), — с `type="module"`. Порядок один и тот же: модульные скрипты без `async` тоже откладываются и выполняются в порядке документа вместе с `defer`, поэтому цепочка `sessions-view.js` → `app.js` → `sessions.js` → остальные сохраняется (`DOCS/decisions/022`).

### Серверные фрагменты (htmx)

Часть интерфейса рисует не браузер, а сервер: шаблон `PROJECTS/<Фича>/<имя>.eta` → роут `/api/fragment/<имя>` → htmx подменяет им кусок страницы. Шаблон лежит в папке своей фичи рядом с её `*-server.js`, который его и рисует (свой экземпляр `Eta` с `views: __dirname`). Сейчас так сделаны панель наблюдения на Home (`PROJECTS/Home/home-observation.eta`, `home-server.js`), список сессий панели Sessions (`PROJECTS/Sessions/session-list.eta`, `sessions-server.js`, `#sessionList`). Кто из сессий выбран (`aria-current`) серверу не известен — это чинит `app.js` в обработчике `htmx:oobAfterSwap` сразу после подмены; лента сообщений выбранной сессии (стриминг NDJSON) на htmx-опрос не ложится и остаётся на JS.

- Куски адресуются через `hx-swap-oob="true"` по `id`: один ответ обновляет несколько мест страницы, а разметку `index.html` и её сетку трогать не нужно. Элемент-инициатор запроса при этом стоит с `hx-swap="none"`.
- Обработчики кликов вешать на контейнер, который htmx **не** подменяет (для Home это `.observation`, для списка сессий — `#sessionsPanel`): слушатель на самом заменяемом элементе переживёт только первое обновление. По той же причине нельзя держать константную JS-ссылку на подменяемый узел (`sessionList` в `app.js` — `let`, а не `const`) — переподхватывать актуальный узел по событию `htmx:oobAfterSwap` (`e.target`).
- Данные подставлять через `<%= %>` — Eta экранирует их сама; `<%~ %>` только для заведомо безопасной разметки. Комментарий в шаблоне — `<% /* … */ %>`, синтаксиса `<%# %>` в Eta 3 нет.
- Ошибка внутри `/api/fragment/*` отдаётся кодом 500, а не привычным `200 { ok: false }` — иначе htmx молча оставит панель замороженной.
- Обновление вне таймера: клиент шлёт событие на `body` (`sessions-changed`), фрагмент слушает его через `hx-trigger="… from:body"`.

# Правила проекта: Карта проекта и память

Часть `AGENTS.override.md`, разложенного по темам: горячие правила и маршрут по типу задачи лежат в самом `AGENTS.override.md`, остальное — здесь. Читать, когда задача про поиск по проекту, карту, заметки в vault и память прошлых сессий.

## Карта проекта и память

Знания о проекте живут в Obsidian-vault внутри репозитория: папка `DATA/vault/` (не коммитится). Сервер создаёт и наполняет её при запуске и обновляет через 3 секунды после правок.

Что в ней лежит:
- `DATA/vault/Project/` — заметка на каждый файл папки проекта (включая скрытые и игнорируемые git; не обходятся только `.git` и `DATA/` — всё, что сервер собрал сам), на его секции и функции, плюс `API/` с заметкой на каждый роут. Связи берутся из настоящих ссылок: литералы `/api/...`, `src`/`href`, `require`, вызовы функций. Роутом считается и сравнение `urlPath === '/api/…'`, и ключ таблицы маршрутов `'/api/…': обработчик` — обе формы равноправны, иначе роут, объявленный таблицей, не стал бы узлом карты.
- `DATA/vault/Sessions/` — память о прошлых сессиях: что просили, чем закончилось, какие файлы затронуты. Помеченные `stale: true` устарели — после них файлы уже менялись.

Правила:
- **Сессия называется — читай её одной командой, не ищи её по папкам.** `node TOOLS/sessions/read.mjs <id>` печатает ходы, ответы, шаги и id внутри CLI. Имя сессии принимается любым из трёх способов: полный id, уникальный префикс, часть заголовка (названием сессии в панели и называется её заголовок). Кнопка копирования в панели Sessions кладёт в буфер готовый адрес вместе с этой командой, поэтому копировать больше нечего и искать не нужно (`DOCS/decisions/099`). **Заметка сессии в `DATA/vault/Sessions/` — это память о былом, а не её содержание:** что просили, чем закончилось, какие файлы затронуты, без самих ходов.
- **Ищи по проекту СНАЧАЛА** командой `node PROJECTS/Graph/search.js "запрос"` — полнотекстовый поиск (FTS5/BM25) по коду, заметкам и прошлым сессиям, выдаёт узел, путь и фрагмент. Фильтр: `node PROJECTS/Graph/search.js --kind session "запрос"`. Индекс собирает сервер; MCP-инструменты `obsidian_*` не используем — они требуют запущенного Obsidian и токена. **Никогда не начинай поиск с `grep -rn` по всему репозиторию, пока не попробовал vault-поиск.**
- **Быстрый поиск — по нескольким ключевым словам вместе.** Для CSS/классов бери точную связку (например: `"provider__model--cascade chat-session-bar"`), а не по одному слову. Это даёт минимум совпадений с первого запроса.
- **Запрещено грести `DATA/`, `.git/`, `node_modules/`** при использовании `bash grep/find/rg` (в них лежат огромные индексы и бинарники: `.db`, `.db-wal`, `.db-shm`). Если всё же вынужден использовать bash-поиск, ОБЯЗАТЕЛЬНО исключай эти пути (`--exclude-dir`/`-path ./DATA -prune -o ...` или `grep ... | grep -v '^./DATA/'`).
- **Не греби бинарники** (`*.db`, `*.db-wal`, `*.db-shm`, архивы) вообще.
- `DATA/vault/Project/` перезаписывается целиком при каждой пересборке. Свои заметки клади в корень vault — их никто не тронет, и они попадут и в граф, и в поиск.
- Отдельной вкладки с графом в интерфейсе нет (`DOCS/decisions/023`): карту читают поиском, приложение Obsidian не открывается. Сама карта на месте — её собирает сервер, из неё же берётся список связей узла в редакторе файла.

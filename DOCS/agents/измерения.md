# Правила проекта: Измерения и упрощение

Часть `AGENTS.override.md`, разложенного по темам: горячие правила и маршрут по типу задачи лежат в самом `AGENTS.override.md`, остальное — здесь. Читать, когда конец задачи или разбор сессии: как не тратить шаги и контекст.

## Измерения и упрощение

- **Считай шаги.** Перед сложной работой кратко скажи план из 2–3 шагов. По итогам (или при анализе сессии) сравни: сколько инструментов реально нужно было vs использовано. Если в 2+ раза больше — сразу предложи одно упрощение.
- **Разведку отдай скрипту.** `node TOOLS/homework/run.mjs "текст задачи"` до первого хода: разведка стоила 122 шага на трёх задачах, с ним — 37 (`DOCS/decisions/084`). Разведка — это 45–58 % всех шагов сессии, и она вся одинаковая; отдавать её модели незачем. Пустой отчёт — ответ, а не беда: спросить человека, какой элемент трогать, дешевле тридцати шагов впустую.
- **Меряй пустые паузы.** Замечай паузы >10с между инструментами — чаще всего многошаговый развед вместо одного точного поиска. Цель: минимальное число чтений.
- **Фиксируй лишний контекст.** Если прочёл файл и не изменил ни строчки — обоснуй, зачем он был нужен. Не читай «на всякий случай».
- **Один точный запрос вместо цепочки.** Всегда сначала `node PROJECTS/Graph/search.js` с 2–4 ключевыми словами вместе. Если 1–2 релевантных файла — читай их, а не копай дальше.
- **Доверяй карте.** Комментарии в заголовках, имена классов/модулей, таблица «Клиентский код» в `DOCS/agents/клиент.md` — часто быстрее `grep`.
- **Исключай мусор.** При bash-поиске никогда не трогай `DATA/`, `.git/`, `node_modules/`. Никогда не ищи по `*.db*` (особенно `*.index.db`, `*.sessions.db*`).
- **`npm run check` — один раз.** После всех правок, перед коммитом.
- **Короткий вывод.** По запросу анализа сессии — 2–4 пункта с конкретными предложениями, без воды.
- **Без автоматических прогонов.** Не предлагай добавлять новые smoke/автотесты/большие серверные прогоны. Смоук удалён (025). Проверки — точечные (`node --check`, eslint/madge, `npm run check`, `npm run ui`/live-verify) там, где они действительно ловят ошибки.

## Чем кончается перерасход (разбор сессии правки стилей)

Пять мест, где шаги и контекст ушли впустую, — все пять ловились бы заранее:

- **Чтение файла правил целиком в каждой сессии.** Правил было 60 КБ, из них задаче понадобились три строки. Отсюда и решение: в `AGENTS.override.md` осталось горячее, остальное — по темам в `DOCS/agents/`.
- **Чтение источника, который не менял.** Класс селекта нашёлся grep'ом сразу, а файл на 390 строк с его логикой прочитан целиком: правило 2 горячего файла.
- **Дамп всего списка вместо двух пунктов.** У селекта 50 пунктов, вернулось 450 строк JSON ради пары цветов. Теперь это делает готовый сценарий `styles` — четыре числа.
- **Снимок там, где нужны были числа.** Два PNG на раскрытый список `select`, а нативный попов в снимок не попадает в принципе: проверить им было нечем.
- **Консоль вместо инструмента чтения и `git status` без путей.** Русский текст из консоли приходит кракозябрами (лишняя итерация), состояние дерева целиком — сотни чужих правок других сессий.

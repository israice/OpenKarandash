# Правила проекта: Живая перезагрузка

Часть `AGENTS.override.md`, разложенного по темам: горячие правила и маршрут по типу задачи лежат в самом `AGENTS.override.md`, остальное — здесь. Читать, когда вопрос «почему после правки всё перезагрузилось» и правила, чтобы одна поломка не гасила интерфейс.

### Живая перезагрузка

Папки `PROJECTS/Penpot`, `TOOLS/penpot-mcp` и `deploy/penpot` сторож не обходит вовсе (`RELOAD_SKIP` в `server.js`): работа с макетом идёт через MCP и пишет файлы рядом с канвасом, а любая такая правка раньше проходила как обычное изменение — страница перезагружалась целиком и запускалась пересборка карты. Это именно живая перезагрузка, а не перезапуск сервера: процесс он не трогает, потому что перезапускается только от `server.js`, `*-server.js` и `SYSTEM/core/*`, а в Penpot таких файлов нет. Правка страницы Penpot, как и прежде, пересобирает только саму страницу — но по F5 вручную. Список задан путями, а не именами папок: в `SKIP_NAMES` (`SYSTEM/core/scan.js`) попадать нельзя, оттуда список общий с картой проекта, и страница исчезла бы из списка проектов.

Сторож файлов смотрит, что именно изменилось, и шлёт точечное событие вместо перезагрузки страницы: правка любого `.eta` перезапрашивает фрагмент по имени его файла (`/api/fragment/<имя>`), правка любого `.css` подменяет `href` у его `<link>`, правка `PROJECTS/<папка>/page.js` пересобирает одну эту страницу кнопки «+» (`MissionPages.rebuildPage`), правка клиентского скрипта переисполняет файл и зовёт его крючок `hotReload` (`App.reloadScript`). Правки, которых страница не грузит (`.md`, `.txt`, `.py`, `.json`, служебные скрипты), страницу не трогают вовсе — раньше любая из них перезагружала её целиком, и это повторялось каждые несколько минут работы над документацией. Пачка правок разбирается пофайлно; полная перезагрузка осталась только для `SYSTEM/index.html` и серверных модулей, после которых процесс всё равно перезапускается. Правило лежит отдельным модулем `SYSTEM/core/reload.js` — его видно и можно позвать напрямую, не поднимая сервера. Подробности — `DOCS/decisions/011`, `DOCS/decisions/090`.

Правила, чтобы одна поломка не гасила интерфейс целиком:
- Раздел живёт в своей папке целиком — вместе с разметкой: её создаёт сам скрипт раздела (Karandash, Settings, Book), а в `index.html` остаются только точки подключения (кнопка тулбара, `<link>` на стили, запись в `App.VIEWS`). Общий механизм, который разделу понадобился, публикуется наружу функцией (`MissionFiles.createFileEditor`, `MdEditors.attach`, `SidebarResize.init`), а не обзаводится знанием про этот раздел у себя. Подробности — `DOCS/decisions/014`.
- Страницы кнопки «+» — тот же раздел, только заведённый пользователем: содержимое каждой лежит в её папке (`PROJECTS/<Страница>/page.js` + `page.css`) и грузится модулем при первом открытии. В `index.html` про них нет вообще ничего: `<main>`, слот в топбаре под свою панель и `<link>` на стили выдаёт загрузчик. Взамен модуль обязан рисовать только в выданных узлах и подписывать всё на `signal` — тогда его правка пересобирает одну эту страницу, не трогая остальной интерфейс. Подробности — `DOCS/decisions/016`.
- Никогда не класть JS обратно в `<script>` внутри `index.html`. Новый кусок интерфейса — новый файл с `defer`: браузер выполняет их независимо, и исключение в одном не отменяет остальные. Файл с `import`/`export` подключается только с `type="module"` — с `defer` браузер откажется его исполнять.
- Чужое (`App.openModal`, `MissionTabs.show`, …) вызывать **внутри функций и обработчиков**, а не на верхнем уровне файла. Тогда порядок загрузки ни на что не влияет и циклические связи безопасны. **Исключение — объявление горячей перезагрузки:** файл, который подключён раньше `app.js` (`settings.js`, `SYSTEM/model-tag.js`), находит `window.App` ещё `undefined`, а `?.` глотает это молча, и объявление просто не происходит. Поэтому объявление всегда идёт в очередь `window.__hotReloads.push([файл, крючок, перерисовка, поставщик])`, а ядро разбирает её лениво. Форма записи — по смыслу, три случая:

```js
// раздел рисует сам: снять своё, свежая копия нарисует заново
push(['PROJECTS/Kanban/kanban.js', () => { /* снять своё */ }]);
// только публикует функцию: рисовать нечего, но узлы перерисовать надо
push(['SYSTEM/model-tag.js', null, () => { /* перерисовать узлы */ }]);
// поставщик: рисует его settings.js, ключ записи — сам поставщик
push(['PROJECTS/Settings/settings-modal.js', null, null, 'PROJECTS/Settings/settings.js']);
```

Ключ записи — всегда первый элемент, «кто рисует этот файл» — последний. Перепутаны местами, объявление молча ничего не делает.
- `app.js` идёт первым (после `book-tab.js`): остальные файлы берут из `window.App` общее ядро. Части, разъехавшиеся из него, берут ядро не из `window`, а `import`-ом из `SYSTEM/app.js` — импорт в обратную сторону (из `app.js` в файл вкладки) запрещён, он даёт цикл.
- Всё, что сервер подставляет в HTML (`{{APP_VERSION}}`, `{{VERSION_LIST}}`), обязано проходить через `escapeHtml` в `server.js` — иначе `<` из сообщения коммита рвёт страницу.

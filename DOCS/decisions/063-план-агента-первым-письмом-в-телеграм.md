# 063. Агент первым письмом говорит в Telegram, как понял поручение

## Решение

Ход, начатый из Telegram (сообщение, ответ на опрос, новая работа после END), получает приставку-правило: до первого инструмента вывести строку `[PLAN] …` — как понял поручение и что сейчас сделает. Общая обвязка хода ловит эту строку из текста по мере прихода и отдаёт событием `plan` только тому, кто начал ход; мост пересылает её человеку письмом «🧭 …», привязанным к работе (ответ reply на него уходит в неё же). Из итогового письма строка плана убирается. Ходы из пульта приставку не получают.

## Почему

- Человек с телефона не видит ленты: до конца работы он не знал, верно ли понят. Дешёвой генерирующей модели у сервера нет (TypeSafe только выбирает из вариантов), а главное — пересказ сторонней моделью показал бы не то, что понял исполнитель. Поэтому план говорит сам исполнитель.
- План после первого шага — уже отчёт: такой не пересылаем (слабые модели сначала хватают инструмент).
- У Hermes текст ответа вживую в ленту не идёт, поэтому план берётся из `assistant.delta`; строка приходит кусками и без перевода строки — её закрывает начало первого шага.
- Мост claude-bridge в потоковом режиме терял слова модели, сказанные вместе с вызовом инструмента (у Hermes оставался пустой content; непотоковый путь их отдавал). Теперь придержанный текст уходит и при вызове — заодно эти пояснения появились в ленте.

## Чем платим

- Приставка — ещё ~400 знаков в каждом ходе из Telegram.
- Модель, не выполнившая правило, плана не даёт: человек получит только итог, как раньше.
- Событие `plan` в базу не пишется: строка и так часть ответа в ленте.

## Что проверено

На сервере владельца: pi с бесплатной моделью — строка поймана, но после шага (не пересылается); Hermes (claude-bridge-sonnet) — `plan` пришёл до первого шага, проза появилась в ленте, три отображения сошлись. Сама доставка письма «🧭» в Telegram не проверена: ход из Telegram может начать только владелец.

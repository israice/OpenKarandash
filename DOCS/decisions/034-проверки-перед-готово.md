# Проверки перед «готово»: одна команда вместо надежды на внимательность

## Решение

`npm run check` (`SYSTEM/checks.js`) прогоняет три проверки и вызывается агентом **отдельным шагом в конце задачи**, до слов «готово»:

| Проверка | Чем делается | Что ловит |
|---|---|---|
| неизвестные имена | `eslint` с единственным правилом `no-undef` (`eslint.config.mjs`) | обращение к переменной, которой нигде нет |
| циклические связи | `madge --circular server.js` | цикл `require`, запрещённый решением `022` |
| размер файлов | обход дерева в `SYSTEM/checks.js` | файл длиннее 400 строк — норма решения `022` |

Первые две валят команду ненулевым кодом. Третья только считает и перечисляет: длинных файлов у нас семь, и провал на них сделал бы проверку бесполезной с первого дня — она превратилась бы в шум, который все обходят. Как только `server.js` и `flow.js` разъедутся, счёт станет нулём сам собой.

Живой прогон интерфейса (агент `ui-checker` через Playwright) в команду не входит: ему нужен сервер, поднятый пользователем (`002`), — из сессии его не запускают. Это отдельный шаг, а не часть `npm run check`.

Правило в `eslint.config.mjs` ровно одно. Стилевые придирки не включаем: они завалили бы вывод шумом и обесценили проверку — из сотни замечаний про кавычки никто не выудит настоящую ошибку.

Конфиг делит код надвое: серверная половина — CommonJS с глобалами Node, всё остальное в `PROJECTS/` и `SYSTEM/` — браузерный код. Имена, которые вкладки публикуют друг для друга через `window` (`App`, `MissionFlow`, `MissionFiles`, …), перечислены явно: для файла-потребителя они приходят извне и объявления не имеют. Новый такой контракт нужно дописать в список, иначе проверка примет его за опечатку.

## Почему

Смоук удалён (`025`), автоматических проверок не осталось вовсе, а хук `syntax-check.js` делает только `node --check` — то есть видит синтаксис и ничего больше. Этого мало, и вот чем это обошлось:

- в `PROJECTS/Settings/settings.js` четыре раза вызывалась функция `pickInstall`, которой в проекте не было: она потерялась при правках, а вызовы остались. Окно настроек падало с `ReferenceError` ровно там, где CLI нашёлся сразу в двух окружениях — а у нас Windows и WSL это норма. Нашла проверка на первом же прогоне;
- в `PROJECTS/Flow/flow.js` жило обращение к `ROOT_FIELDS`, которую не успели написать: любая панель карточки агента упала бы у обеих ролей сразу.

Обе ошибки синтаксически безупречны. Обе падают только в браузере у пользователя. Обе ловятся `no-undef` за секунды.

## Чем платим

Три dev-зависимости (`eslint`, `globals`, `madge`), версии закреплены точным номером. Правило `AGENTS.md` требует обосновывать каждую: обоснование — найденный на первом прогоне живой баг, который иначе обнаружил бы пользователь.

Проверка не заменяет живой прогон интерфейса: она не видит упавший обработчик, пустую панель или сломанную вёрстку. Она закрывает ровно один класс ошибок — зато закрывает целиком и без участия человека.

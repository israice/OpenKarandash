# Hermes: история из кеша, служебные вызовы на Haiku, помехи контейнера убраны

> Записка раньше носила номер `039` — тот же номер получила «Лента хода Hermes пересобирается по его истории», и ссылки на «039» стали неразрешимы. Номер `039` оставлен за лентой, на которую указывали почти все ссылки; эта записка стала `041` (`OpenKarandash-f59.19`). Старая ссылка `DOCS/decisions/039` про кеш сессий моста, служебные вызовы на Haiku или настройки контейнера означает именно этот файл.

## Решение

1. **Мост продолжает сессию claude CLI между шагами агента** (`claude-bridge/session_cache.py`). Ход с инструментами идёт в сохраняемую сессию CLI, индекс помнит «переписка + ответ → id сессии», и следующий запрос с тем же началом уходит через `--resume` только новыми сообщениями. Совпадение ищется по цепочке хешей отрисованных сообщений; любое расхождение — промах, ход идёт полной перепиской, как раньше, а в `logs/bridge.log` пишется, какое сообщение разошлось (`no resume: … message N differs`). Выключается `CLAUDE_BRIDGE_SESSION_REUSE=0`.
2. **Мост отдаёт признаки жизни и кеш.** Пустой кусок потока раз в 15 с тишины, размышления — по мере появления; `usage.prompt_tokens_details.cached_tokens` / `cache_write_tokens`. Если Hermes отключился, процесс CLI убивается. `--effort` — одна настройка на весь мост (`CLAUDE_BRIDGE_EFFORT`), по умолчанию как решит CLI.
3. **Настройки Hermes** (`hermes-home/config.yaml`, образец — `hermes-home.config.example.yaml`):
   - `platform_toolsets.api_server` — без браузера, tts, генерации картинок и Home Assistant;
   - `auxiliary.approval`, `title_generation`, `background_review` — `claude-bridge-haiku`, у фоновой проверки потолок 200 тыс. входных токенов;
   - `approvals.unattended_mode: approve` — `execute_code` в контейнере разрешён, опасные команды терминала по-прежнему проходят смарт-проверку;
   - `file_read_max_chars: 40000`;
   - `agent.environment_hint` — что в контейнере работает иначе: базы на смонтированном диске, поиск и API сервера вместо них, нет PowerShell.
4. **git в репозитории не смотрит в подмодуль `hermes/`** (`diff.ignoreSubmodules=all`, ставит `SYSTEM/core/hermes-stack.js`).
5. **`search.js` при недоступной базе спрашивает сервер** (`/api/search`, у которого появился фильтр `kind`).
6. Навык Hermes `openkarandash-dev` вычищен от обходов, которые больше не нужны или стали неверны.

## Почему

Разбор 23 сессий Hermes 2026-09-17 (одна из них — 85 вызовов модели, 8,5 млн входных токенов, 0 из кеша, 2 ч 14 мин):

- История уходила в CLI одним текстовым блоком с меняющимся хвостом (напоминание протокола, метка `Assistant:`). Кеш Anthropic совпадает по границам блоков, поэтому история на каждом шаге заново писалась в кеш и ни разу не читалась. Замер после правки: 96–99% ввода из кеша, 4–6 с на шаг с инструментом вместо 30–240 с.
- Промахи продолжения на первом прогоне показали два расхождения, которые Hermes вносит сам: он сортирует ключи аргументов вызова и не возвращает короткую фразу перед вызовом. Оба учтены в нормализации ключа.
- Фоновая проверка после ходов шла на Sonnet со всей перепиской: 23 запуска — 5,6 млн входных токенов за два дня. Проверка команд моделью — 71–122 вызова Sonnet. Самообучение не выключено, перенесено на Haiku: чужой модели Hermes даёт сжатый пересказ, а не всю переписку.
- `execute_code` в API-сессиях Hermes считает «безлюдным» и при штатном `deny` блокирует целиком — модель тратила ходы на заведомо отклонённый вызов и обходила его через `write_file` + `terminal`. Контейнер сам по себе песочница.
- `git status` проверял клон `hermes/` (1,1 ГБ, записан в индекс подмодулем): 18 с на хосте, больше 300 с из контейнера — 12 таймаутов за 4 дня и круги модели вокруг «зависшего git». Сейчас 1 с на хосте и 2 с в контейнере.
- `DATA/*.db` в режиме WAL через смонтированный диск дают `disk I/O error` — `search.js`, который велит использовать `AGENTS.override.md`, из контейнера не работал, и модель копировала базы и выгружала дампы по 30–40 тыс. символов в контекст, ускоряя сжатие, после которого всё перечитывалось.

## Чем платим

- Сессии моста лежат файлами в `~/.claude/projects/<…DATA-bridge-sessions>/` (удаляются через 24 ч) и индекс `DATA/bridge-sessions/index.json`.
- Модель в продолженной сессии видит свои прошлые ответы в том виде, как написала их сама, а Hermes — в разобранном; по смыслу это одно и то же.
- Проверка опасных команд на Haiku слабее, чем на Sonnet; жёсткий запрет Hermes (`_floor_block`) от модели не зависит.
- `diff.ignoreSubmodules=all` скрывает изменения внутри любых подмодулей из `git status`/`git diff`; своих подмодулей, кроме `hermes/`, в проекте нет.
- Новые ключи образца конфига попадают только в свежий `hermes-home/`: существующий `config.yaml` стек не перезаписывает.

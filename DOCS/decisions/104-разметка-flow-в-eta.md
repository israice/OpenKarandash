# Разметка вкладки Flow переехала в PROJECTS/Flow/flow.eta

## Решение

Разметка вкладки Flow (боковая панель и полотно, ~600 строк) вышла из `SYSTEM/index.html` в `PROJECTS/Flow/flow.eta` и отдаётся маршрутом `/api/fragment/flow` (шаблон с `views = __dirname`, `cache: false`, ответ через `sendHtml`). В `index.html` осталось только `<div class="view view--side" id="flowView" hidden>` с контейнером `<div id="flowBody" hx-get="/api/fragment/flow" hx-trigger="load" hx-swap="innerHTML">`.

Клиентский код Flow теперь ждёт появления разметки: `flow.js` и `flow-session-sync.js` ждут `#flowCanvas` / `#flowNav` (опрос 50 мс, потолок 10 с), прежде чем трогать DOM — иначе init падал бы на `document.getElementById('flowNodeStartMeta')` и FlowCanvas. `SYSTEM/boot.js` учитывает первый запрос фрагмента самими же своими хуками на `htmx:beforeRequest`, так что страница по-прежнему показывается только после сборки.

Это первый шаг пункта 3 «Порядок работ» из `DOCS/целевая-архитектура.md`: компонент как шаблон + маршрут + один id. Та же схема уже работает у `session-list.eta` (`/api/fragment/session-list`) и `telegram-messages.eta` (`/api/fragment/telegram-messages`); Flow — последний крупный инлайн-кусок, оставшийся в index.html.

Права сразу меняются и на горячую перезагрузку: правка `flow.eta` отныне доезжает точечной подменой фрагмента (`watch.js` swapFragment по `hx-get` узлу) вместо полной перезагрузки страницы, а правка `flow.css` — без перезагрузки вовсе. Canvas-состояние JS (ноды, рёбра) живет в памяти модулей, поэтому после такой точечной подмены канвас нужно пересобрать (следующий запуск графа из сессии); для разработческой правки это приемлемо и не трогает серверные данные.

## Почему

Целевая архитектура требует: у компонента одно место жительства — шаблон рядом с его скриптом и стилями, а не кусок в общем `index.html`. Пока разметка Flow лежала в `index.html`, правка вкладки требовала держать в голове чужой 850-строчный файл и ломала точечную перезагрузку (любое чтение меняло всю страницу).

Дополнительно это снимает скрытую связность: раньше `flow-session-sync.js` и `flow.js` silent safety depended on defer-скрипты выполнившись над готовым DOM — теперь контракт явный, через ожидание появления разметки и событие `flow-ready`.

## Чем платим

- Вкладка Flow зависит от одного дополнительного HTTP-запроса на старте (~мс на локальном сервере); boot.js уже считает его среди задач первой сборки.
- Если `/api/fragment/flow` не доедет — Flow не инициализируется: вместо пустого холста внутри страницы теперь «нет графа», и заслон boot.js всё равно снимается по простою 8 с.
- Горячая правка .eta точечной подменой не пересобирает JS-состояние канваса (см. выше): для проверки свежего flow.eta надёжнее обновить страницу.

# 075. В интерфейсе один агент — OpenCode

## Решение

После удаления Claude (`DOCS/decisions/074`) владелец велел убрать из проекта
Codex и pi. Вместе с ними ушло всё, что существовало только ради них:

- `PROVIDERS` в `SYSTEM/providers.js` — одна запись, `opencode`; `STORE_KEYS` и
  `DEFAULT_ORDER` по одному ключу.
- Карточки в `PROJECTS/Settings/settings.js`: `connectCodex`, `connectPi`, ветки
  клика по ним, поле ключа OpenRouter (оно было нужно pi, чтобы free router
  ожил) и вся разметка `provider__model--key`.
- Коннекторы `codex` и `pi` в `server.js` вместе со своими целями запуска,
  `detect`, `ask`, `CODEX_BIN`/`PI_BIN`, `savePiOpenRouterKey` и ключом
  `openRouterKey` в теле `/api/agent/connect`. `FREE_AGENTS` — один элемент.
- `effort` как единица интерфейса: последний CLI, который его брал на клиенте,
  был pi. Удалены select в шапке сессии (`#chatSessionEffortSelect` в
  `SYSTEM/index.html`, поле в `chat-state.js`, обработчик в `chat.js`), ветка
  `provider.efforts` в `renderSessionModelEffort`, строка effort в карточке
  Settings и отправка `effort` в теле хода. На сервере `EFFORT_LEVELS` остался —
  его принимает Hermes.

Место под следующего агента оставлено: строка выбора провайдера в шапке сессии,
список карточек в Settings, таблица `AGENTS` на сервере и ключ в `localStorage` —
всё это работает с любым числом провайдеров и сегодня показывает один вариант
выбора. Новый коннектор по-прежнему заводится строкой в таблице `AGENTS`.

## Почему

Три агента в интерфейсе стоили содержания, которого не давал результат: три
карточки, три функции подключения, три набора целей запуска, отдельное поле
ключа, отдельный select уровня размышления, три ключа в `localStorage` — и всё
это ради вариантов, которыми владелец не пользуется. Решение владельца 2026-10-01:
один агент, OpenCode.

## Чем платим

- **Запасного исполнителя у хода больше нет.** Список бесплатных моделей
  (`FREE_AGENTS`) остался один агент, а платной подписки в таблице не осталось:
  когда модель OpenCode падает, работу подхватывает только Hermes, и то если он
  поднят (`AGENTS.hermes.connected()`, см. решение 074). Если Hermes выключен
  (`HERMES_STACK=0`), упавший ход доходит до человека письмом об ошибке — это
  ожидаемое поведение при одном агенте, а не поломка.
- **Старые сессии Codex и pi остаются в списке.** Их `target` начинается с имени
  удалённого коннектора, `agentNameByTarget` отдаёт для них `DEFAULT_AGENT`
  (opencode) — так же, как раньше отдавала его для целей коннектора Claude.
  История при этом читается целиком, ничего не теряется.
- **Вкладка, открытая до обновления,** позовёт `detect`/`connect`/`ask` с именем
  удалённого агента. Раньше это было бы 500; теперь все три маршрута отвечают
  честным отказом — `Unknown agent: …` в теле (`DOCS/decisions/022`: ошибку,
  которую обработчик предвидит, отдаёт сам).
- **Три записи в записке 037** (этапы 4–5 плана переноса коннекторов на
  exec-bridge) отменены: переносить нечего. Сама схема моста и её клиент
  `execViaBridge` в `server.js` не тронуты.

## Что проверено

`npm run check` (неизвестные имена, циклы) и `npm run ui` — все вкладки, страницы
«+», окно настроек. Живой прогон на сервере владельца: в настройках одна карточка
**OpenCode** в секции Free, после Connect — `WSL · CLI 1.18.32`, в строке выбора
над сессией одна опция `OpenCode`, select effort на странице отсутствует, ошибок в
консоли нет; короткий ход из композера дошёл до ответа и лёг в базу (сессия
`opencode-wsl-mupuhdj4`, удалена за собой).

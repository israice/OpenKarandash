# Строка выбора модели отвечает, даже когда каталога ещё нет

## Решение

Два правила в строке выбора над сессией (`#chatSessionBar`, четыре уровня
CLI / Gateway / Model / Effort):

1. **Уровень с настоящим значением не остаётся выключенным.** Наполнитель
   (`fillLevel` в `SYSTEM/model-cascade-fill.js`) выключает уровень, когда
   список значений пуст, — а значение, которое в уровне показать есть,
   добавляется после (`keepAbsent`). Раньше уровень оставался выключенным с
   готовым значением внутри: список не открывался, и выбрать было нечем.
   Теперь `keepAbsent` (он переехал в `model-cascade-fill.js` — наполнение
   уровня) включает уровень обратно.

2. **Каталог моделей берётся сразу после смены CLI.** Уровень Model
   наполняется каталогом, который отдал сам CLI, а у неподключённого CLI
   каталога нет: список пуст, и выбрать модель не из чего. Подключение делает
   ход (`ensureConnected`), но это уже после выбора, а человек меняет CLI
   именно затем, чтобы выбрать модель. Поэтому при смене CLI строка зовёт то
   же подключение, что и ход (`App.ensureConnected` в `SYSTEM/app.js`), каталог
   приходит — строка перерисовывается сама, и выбор в ней сохраняется.

## Почему

Жалоба владельца 2026-10-21: «не удается выбрать, некоторые выпадающие меню не
реагируют». Проверено в безголовом Edge на настоящих стилях и настоящих
модулях (`SYSTEM/session-model-bar.js`):

| состояние | CLI | Gateway | Model |
|---|---|---|---|
| CLI подключён, каталог есть | отвечает | отвечает | отвечает, 142 модели |
| CLI выбран, но не подключён | отвечает | отвечает | **было выключено** |
| CLI не установлен | отвечает | отвечает | **было выключено** |

Строка выбора перечисляет все имена CLI с сайта (51 штука), а подключён в
каждый момент один: `activateExclusive` забывает остальных. Переключил CLI —
и список Model оказался выключенным, с моделью внутри, но без возможности её
выбрать. Это и есть «не удаётся выбрать» и «некоторые выпадающие меню не
реагируют»: мёртвый список не открывается.

## Чем платим

Смена CLI теперь стоит подключения CLI: сервер запускает его, чтобы узнать
каталог (`/api/agent/connect` → `version` + `models`). Это то же подключение,
которое иначе случилось бы перед ходом, — просто раньше. Для CLI, которого на
машине нет, подключение не выходит (`detect` ничего не находит), и строка
остаётся как была.

Подключение идёт фоном: список выбора не блокируется, а перерисовывается
сам, когда каталог пришёл. Человек, открывший список в эти секунды, увидит,
как список обновится, — уровень Model после перерисовки сохраняет выбор.

## Что не менялось

- Каталог моделей по-прежнему приходит от самого CLI и только от него.
- Уровни выбора по-прежнему общие на все CLI (ключ один), и переключение CLI
  не стирает ни одну из половин выбора.
- Подключение по-прежнему делает и ход: строка не отменяет его, а только
  делает раньше — иначе список модели нечем наполнить.
- Модель в ход уходит ровно та, что стоит в уровне Model (`getActiveModel`).

## Проверено

Безголовый Edge, настоящие стили и настоящие модули, страница-подмена с
каталогами по форме решения 119 (opencode — 11 своих бесплатных и 142 чужих,
kilo, omp, pi):

- смена CLI на подключённый: каталог пришёл, Gateway и Model перечисляют его
  модели, оба уровня отвечают;
- выбор модели: значение осталось, сохранённые уровни совпали с показанным
  (`gateway=kilo, provider=anthropic, model=claude-fable-latest`);
- смена CLI на неустановленный: список Model отвечает и показывает выбранное
  значение (раньше был выключен);
- `npm run check` EXIT=0.

Не проверено: живой сервер владельца (002) — живой ход с моделью, выбранной
после смены CLI, не гонялся.

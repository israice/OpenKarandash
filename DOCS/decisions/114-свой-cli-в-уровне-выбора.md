# 114. Свой CLI в списке уровня выбора

**Основание:** запрос владельца 2026-10-07: в списке CLI в шапке сессии над списком
с сайта должен стоять `opencode` — как наше собственное решение, независимо от
того, назвал его OpenRouter или нет. Если сайт его назовёт — из того списка он
убирается, чтобы в раскрытом списке не было двух одинаковых строк.

## Владелец

Список имён CLI принадлежит `SYSTEM/cli-agents.js`: там уже лежит и список с
сайта, и снимок, и их сверка. Своё имя добавлено туда же, потому что это тот же
вопрос — «какие имена может назвать уровень CLI» — и второй список рядом
разошёлся бы с первым при первой же проверке сайта.

- `OWN_CLI` — наши имена, объявлены в этом же файле.
- `cliLevelNames(extra)` — порядок для уровня каскада: сперва `OWN_CLI`, потом
  сайт без них, потом подключённый CLI (его добавляет вызывающий). Наборы
  сливаются в один без повторов.

Потребители переведены на неё оба: `SYSTEM/model-cascade.js` (строка выбора) и
`SYSTEM/session-model-bar.js` (список своих для шапки). Раньше каждый собирал
`[...new Set([...cliAgentNames(), ...свои])]` сам, и наше имя в обоих местах
пришлось бы поставить дважды.

## Что сознательно не делаем

- Не трогаем `cliAgentNames()` и `isStubCli()`: это ответ про то, что пришло с
  сайта, и про то, у кого нет своего коннектора. `opencode` в списке сайта не
  значит «заглушка» — у него есть коннектор (общий `any.js`), и выводить его
  оттуда нельзя.
- Не пишем своё имя в `SNAPSHOT`: снимок — это то, что сайт вернул, и подмена
  его своим именем сделала бы проверку списка бессмысленной (она сравнивает
  пришедшее с сохранённым).

## Проверки

- `cliLevelNames` без браузера: первым `opencode`, в списке сайта его нет,
  дублей нет, длина 50 = 1 + 49, подключённый CLI не теряется.
- `npm run check` чисто.
- Живой список в шапке — за владельцем (002).

## Альтернативы, которые не выбрали

- Дописать `opencode` в `SNAPSHOT` — список с сайта перестал бы быть списком с
  сайта, и любая проверка обновления начала бы врать.
- Обрабатывать имя в самом каскаде — правка в `model-cascade.js` и в шапке
  разошлась бы при первом же новом потребителе списка.

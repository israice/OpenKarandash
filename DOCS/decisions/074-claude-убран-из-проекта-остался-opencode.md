# 074. Claude убран из проекта как агент хода, остался OpenCode

## Решение

Claude вычеркнут из проекта как **провайдер хода**: его нет в `PROVIDERS`
(`SYSTEM/providers.js`), в карточках Settings, в строке выбора агента над
сессией и в таблице коннекторов `AGENTS` в `server.js`. Агентом проекта и
единственным, кого владелец выбирает в интерфейсе, остался OpenCode
(`DEFAULT_AGENT`).

Про Codex и pi, оставленные в списке запасными, владелец после этого решил то же
(`DOCS/decisions/075`): в интерфейсе остался один агент.

Вместе с провайдером ушли только его собственные куски: коннектор
(`TARGETS`/`runClaude`/`askClaude` и разбор `stream-json`), автоподключение при
старте (`autoConnectClaude`, `CLAUDE_AUTOCONNECT`), маршрут `/api/agent/status`,
лимиты подписки (`updateClaudeUsage`, `renderUsageInline`, строка usage в
Settings) и старое имя отправки хода — `sendToClaude`/`stopClaude` стали
`sendTurn`/`stopTurn`, потому что ход ведёт тот агент, кого выбрали.

**Не тронуто:** сам `claude` CLI, `claude-bridge/` и `hermes-home.config.example.yaml`.
Мозг Hermes — это `claude-bridge-*`, и мост на хосте
продолжает гонять тот же CLI. Проверка хоста (`SYSTEM/core/host-deps.js`)
по-прежнему ставит и логинит его, а найденное окружение отдаёт мосту напрямую
(`hermesStack.setClaudeTarget`) — раньше это делал коннектор Claude через
`/api/agent/status`.

## Почему

Решение владельца: один агент в интерфейсе вместо четырёх. Пока Claude стоял
рядом с OpenCode, каждая мелочь вокруг него требовала отдельного содержания —
свой ключ в `localStorage`, своя карточка, свой разбор лимитов, свой автоподхват
при старте, который возвращал Claude над чатом, если у человека не было
сохранённого выбора. С провайдером, которым не пользуются, эта работа не
окупается ничего.

Второе следствие видно из кода: `hermesReady()` был гейтом **каждого** хода
коннектора Claude — только через него Hermes вообще попадал в разговор из
браузера. С убранным коннектором гейта нет, поэтому `hermesReady()` теперь
прогоняется один раз при старте `server.js`: он дожидается подъёма контейнера и
зажигает `activeHermesTarget`, после чего коннектор `hermes` честно отвечает
`connected()` и его можно назвать запасным исполнителем (`readyExecutor`) для
новой работы, у которой нет прямого владельца.

## Чем платим

Три вещи, которые стоит знать:

- Hermes больше не вызывается из сессии, начатой прямым CLI, — так и было
  задумано (`DOCS/decisions/043`): ведёт её тот, кто её начал. Для новой
  работы без владельца он остаётся запасным исполнителем.
- Старые сессии, чей `target` не принадлежит ни одному коннектору (цели вида
  `wsl`/`windows`/`custom` от коннектора Claude), приписываются
  `DEFAULT_AGENT`, как и раньше: `agentNameByTarget` отдаёт `DEFAULT_AGENT` всему
  незнакомому.
- Лимитов подписки в пульте больше нет. Их присылал только Claude CLI
  (`rate_limit_event`); остальные коннекторы таких событий не шлют, и показывать
  пустую строку было бы враньём.

## Что проверено

`npm run check` (неизвестные имена, циклы) и `npm run ui` — все вкладки, окно
настроек, страницы «+». Живой короткий ход на сервере владельца (`short-turn` в
`live-verify`) прошёл под OpenCode, сессия легла в базу.

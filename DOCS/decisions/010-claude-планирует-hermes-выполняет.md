# Claude планирует, Hermes выполняет

**Решение.** В списке провайдеров есть связка «Claude → Hermes» (`hermes-plan`). Один запрос человека проходит два хода в одной сессии:

1. **Claude** — наш CLI, наш способ запуска, режим `Chat` (`--permission-mode plan`): он ничего не меняет, а превращает текст человека в точное задание для исполнителя. Задание показывается в чате целиком.
2. **Hermes** — режим `Action`: получает это задание и выполняет. Внутри он дробит его на подзадачи и раздаёт своим подагентам.

**Почему так, а не наоборот.** У Claude большое контекстное окно, он разбирается в незнакомом коде и идёт по подписке CLI — планирование дёшево именно у него. У Hermes подзадачи выполняют подагенты, и там уходит основная масса токенов — значит, там и надо экономить. Это штатный рычаг Hermes: `delegation.model` и `delegation.provider` держат подагентов на дешёвой (вплоть до бесплатной) модели, пока планирование остаётся у сильной. В настройках это поле «Модель подзадач», провайдер для него — OpenRouter.

**Одна сессия на оба хода.** Hermes пишет в ту же сессию, которую завёл Claude: человек видит подряд свой текст, задание от Claude и результат Hermes. Владельца сессии второй ход **не перебивает** — колонка `target` остаётся claude'овой, иначе продолжить сессию тем же CLI стало бы нельзя. Кто выполнил конкретный ход, видно в `result_meta` сообщения (`executor`, `target`, `provider`, `model`, `hermesSessionId`).

**Что здесь не используется намеренно.** У Hermes есть свой навык `claude-code`, который умеет звать `claude -p` самостоятельно. Мы им не пользуемся: он запускал бы Claude мимо нашего сервера — мимо очереди по файлам, блокировки `/api/agent/lock-check`, выбора цели (Windows/WSL) и записи в историю сессий. Claude в этом проекте запускается ровно одним способом, и связка идёт через него же.

**Чем платим.** Каждый запрос — это как минимум два запуска CLI, и ответ приходит не сразу. Взамен: планирует тот, кто умеет, а платим за исполнение по дешёвому тарифу.

**Проверено.** Связка отказывается работать, если подключён не весь состав (проверка в смоуке). Живой прогон целиком не делался: нужен ключ OpenRouter для моделей подзадач.


## Переключение исполнителя посреди сессии

Раньше сессия принадлежала тому CLI, который её начал: попытка продолжить другим отклонялась словами «Сессия начата через … — продолжить её можно только тем же CLI». Правило снято.

Причина запрета была настоящей: `--resume` берёт историю из хранилища самого CLI, и чужой id там не найдётся — у Claude и OpenCode они разные, и даже у Windows-claude и WSL-claude разные папки историй. Но это причина не запрещать переключение, а не передавать чужой id.

Как сделано: наш id сессии больше не равен id внутри CLI. В таблице `session_cli` лежит по одной записи на пару «сессия + цель»: id, который выдал именно этот CLI. Продолжаем только своим id; если у цели своей записи нет, она начинает собственную сессию, а контекст получает пересказом — последние ходы переписки из нашей базы идут впереди запроса (`handoffPreamble`). Переписка в интерфейсе остаётся одной.

Связка «Claude → Hermes» пересказ не запрашивает: задание от Claude и есть весь нужный контекст, пересказ повторил бы его вторым экземпляром.

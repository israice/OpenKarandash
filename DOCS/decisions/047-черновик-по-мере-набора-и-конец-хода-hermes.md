# Текст по мере набора — черновик мимо базы; у хода Hermes три конца, а не один

## Решение

**Прямой коннектор Claude** (`askClaude` в `server.js`) запускает CLI с `--include-partial-messages`, как это уже делает мост (`claude-bridge/cli_process.py`). Куски `stream_event` → `content_block_delta` (`text_delta`, `thinking_delta`) копятся и раз в `DELTA_FLUSH_MS` уходят событием `{ type: 'delta', kind, text }` через `ctx.emitLive`. Это черновик:

- в базу он не пишется — следом CLI присылает целое сообщение, и строка рождается из него, как раньше;
- номера `seq` не получает и в буфер хода (`DOCS/decisions/046`) не ложится — иначе десятки кусков в секунду вытеснили бы из буфера настоящие события, и догон после обрыва перестал бы работать;
- уходит только тому, кто попросил: отправителю запроса и подключившимся с `deltas: true` в `/api/sessions/attach`. Просит одна лента Sessions (`PROJECTS/Chat/chat-stream.js`, `makeRenderer`): она рисует черновик и снимает его любым следующим событием. Feed и Flow на каждый пришедший байт перечитывают базу, а в базе черновика нет — им куски дали бы только пустые перечитывания. Содержимое ленты во всех трёх отображениях при этом одинаково: черновик — способ показать ту же строку раньше, а не отдельная строка.

**Поток Hermes** (`askHermes`, `onEvent`). Ход Hermes кончается одним из трёх событий — `run.completed`, `run.failed`, `run.cancelled` (`terminal_run_status` в его `api_server_runs.py`), и расшифровку с расходом несут все три. Разбирался только первый: у хода, оборванного лимитом шагов или остановленного, пропадали вывод инструментов и токены. Теперь все три идут одной веткой (`HERMES_TERMINAL_EVENTS`), а несостоявшийся конец оставляет в ленте пометку `hermes.run.failed` / `hermes.run.cancelled` с причиной (`turn_exit_reason`).

Событие, под которое ветки нет, пишет `recordTopLevelEvent` с типом `hermes:<имя>` — тот же принцип, что у стрима CLI (`DOCS/decisions/012`). Мимо идут только заведомо пустые для ленты (`HERMES_SILENT_EVENTS`): `run.started`, `message.started`, `assistant.delta`, `done`.

**Размышление, показанное вживую, переживает пересборку хода.** Пересборка (`rebuild` в `SYSTEM/core/hermes-history.js`) стирает строки потока и пишет ход заново по истории Hermes, а `reasoning_content` в истории бывает пуст — строка размышления исчезала из базы, хотя человек её только что видел. Теперь `askHermes` отдаёт пересборке тексты живых размышлений (`liveThoughts`) с числом шагов до каждого; если в истории размышлений нет, они встают на свои места.

## Чего не сделали и почему

`--input-format stream-json` в прямой коннектор не перенесён. Мосту он нужен, чтобы отдавать модели структурное содержимое (результаты инструментов Hermes); прямой коннектор шлёт один текст через stdin, и смена формата ввода ничего бы не дала, а проверить её живьём нельзя: пока поднят Hermes, все ходы идут через него (`hermesReady`), прямой путь — запасной.

Куски `assistant.delta` от Hermes в черновик тоже не идут: в них бывает вызов инструмента, написанный текстом, который мост потом переоформляет, — человек увидел бы сырой JSON.

## Что проверено

Форма событий CLI снята настоящим запуском `claude -p --include-partial-messages` (86 `thinking_delta`, 3 `text_delta`, поле `parent_tool_use_id` на месте). Ход через Hermes на живом сервере: номера событий без пропусков, лишних строк `hermes:*` нет; до правки пересборки в базе было `user,tool,assistant` при показанном вживую размышлении (сессия `hermes-docker-mu7owdmb`), после — `user,system,tool,thinking,assistant` (`hermes-docker-mu7oyce3`), и строка Reasoning видна в Sessions, Feed и Flow. Ветки `run.failed`/`run.cancelled` живьём не вызывались — оборванного хода под рукой не было. Прямой путь с черновиком живьём не проверялся по причине выше.

# WSL-клиенту открыт ровно один маршрут

**Решение.** Хук `.claude/hooks/file-lock.js` под WSL стучится на сервер не по `127.0.0.1`, а по адресу шлюза по умолчанию (берётся из `/proc/net/route`). Со стороны сервера `isWslRequest()` узнаёт этот адрес по маске адаптера «vEthernet (WSL)» и пускает такие запросы **только** на `/api/agent/lock-check`.

**Почему.** В виртуалке `127.0.0.1` — её собственный loopback, до сервера на Windows он не ведёт. При этом открывать виртуалке всё API незачем: чтение и запись файлов, запуск CLI ей не нужны — WSL-claude правит файлы напрямую через `/mnt/c/...`. Единственное, ради чего ему нужен сервер, — спросить, не занят ли файл другой сессией.

**Чем платим.** Одно исключение в проверке источника запроса, которое надо помнить при любой правке маршрутизации. Путь `lock-check` поэтому нельзя переименовывать свободно: он зашит и в хук, и в это исключение.

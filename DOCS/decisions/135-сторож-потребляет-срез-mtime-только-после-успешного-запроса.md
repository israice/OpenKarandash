# 135 — сторож потребляет срез mtime только после успешного запроса

## Что случилось

Правки серверных файлов перестали доезжать до живого сервера: коммит
`a6ab076` (v0.0.200, фикс доведённых ходов) изменял `SYSTEM/cli/any-parse.js`,
а сервер продолжал работать на коде, загруженном при старте 15:58. Замер
сторожа тикает каждые 400 мс, все 71 наблюдаемый файл разбираются — а
перезапуска нет.

## Почему

В замере сторожа срез времени изменения файлов потреблялся **до** проверки:

```js
const current = latestMtime(watchedFiles());
if (current === mtime) return;
mtime = current;   // срез съеден заранее
restart();         // внутри — isValid(): если он упал, правка потеряна навсегда
```

`restart()` начинается с `isValid()` — прогона `node --check` по всем
наблюдаемым файлам. Если в момент замера хоть один файл был на полузаписи
(git переписывает соседние файлы коммита), проверка падала, замер выходил,
а срез уже был съеден: следующий тик видел `current === mtime` и уходил.
Правка пропускалась навеки — ровно тот случай, ради которого комментарий
в коде обещал «починят файл — mtime изменится, и мы придём сюда снова».
Та же схема была в ветке собственного кода сторожа (`ownFiles`).

## Решение

`restart()` теперь возвращает признак успеха, и замер потребляет срез
только после него:

```js
if (restart()) mtime = current;
```

Провалившийся `isValid()` оставляет правку несъеденной — она придёт
снова на следующем тике, хоть каждые 400 мс, пока файлы не станут
разбираться. Уже запрошенный перезапуск (`restarting`) считается успехом:
срез потреблять можно, потерять ничего.

## Чем платим

Пока в наблюдаемых файлах лежит неразбираемый код, каждый тик (400 мс)
гоняет `node --check` по всем файлам зря. Это дороже молчаливой потери
правок; неразбираемый код в дереве — аварийное состояние, а не режим.

## Как заметили

Сессия «анализируй почему сессия прервалась» получила продолжения хода
после собственного фикса: сервер ещё не открывал новый `any-parse.js`,
а отметка версии в топбаре читает `VERSION.md` с диска и показывает
v0.0.200 на процессе с кодом v0.0.199. Наглядный урок: живость кода
проверяется не файлом версии, а `DATA/server.lock` → `startedAt` и
новой строкой в `DATA/server-exits.log` после коммита.

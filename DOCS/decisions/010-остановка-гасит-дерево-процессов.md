# 010. Кнопка Stop гасит дерево процессов, а не одну обёртку

## Проблема

`stopActiveRun` делал `child.kill()` — убивал ровно тот процесс, который породил сам сервер.
Этого мало в двух случаях, и оба у нас основные:

- **Цель WSL.** Сервер запускает `wsl.exe bash -lc "claude ..."`. Убитой оказывается
  обёртка `wsl.exe`, а сам `claude` работает внутри виртуалки, в её собственном
  пространстве процессов, и потомком `wsl.exe` с точки зрения Windows не является —
  он продолжает работать, править файлы и тратить лимит.
- **Windows вообще.** Сигналов там нет; потомки принудительно завершённого процесса
  переживают его.

Снаружи это выглядело как «кнопка Stop перестала останавливать текущую сессию».

## Решение

`killProcessTree(child, target)` в `server.js`:

1. Запуск через шелл (`target.viaShell`) первым делом печатает в stderr свой PID
   внутри виртуалки — `echo __karandash_pid__$$ >&2; exec claude ...`. `exec`
   обязателен: без него `claude` станет потомком `bash`, и `$$` укажет не на него.
   Служебную строку вырезает `takeRemotePid`, чтобы она не попала в текст ошибки.
   Остановка шлёт по этому номеру `kill -TERM` тем же `wsl.exe`.
2. На Windows дополнительно `taskkill /pid <pid> /T /F` — `/T` забирает потомков.
3. `child.kill()` остаётся как общий случай.

`run` в `activeRuns` теперь помнит свою `target` — без неё остановка не знает,
шла ли работа через шелл. Тем же путём гасится и запуск, превысивший таймаут.

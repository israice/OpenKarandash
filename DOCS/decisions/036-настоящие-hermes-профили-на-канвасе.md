# 036. Настоящие hermes-профили на канвасе Flow

Помимо выдуманных ролей (QA, Backend developer — DOCS/decisions/033), в проекте есть
четыре **реально существующих** каталога Hermes: `hermes-home/profiles/developer`,
`docs-writer`, `qa-checker`, `reviewer`. Их создаёт и монтирует сам Hermes-стек
(DOCS/decisions/029) — это не наши файлы-заготовки, а настоящий `config.yaml`,
`profile.yaml`, `SOUL.md`, `skills/`, `memories/`, `sessions/`, `state.db` каждого
агента.

## Решение

Завести для этих четырёх профилей карточки на канвасе Flow (меню «Profiles»,
AGENT_ICONS: Developer 💻, Docs writer 📝, QA checker 🔬, Reviewer 🔎) — но не
четыре новых шаблона разметки, а переиспользовать уже существующий общий
`#flowNodeProfileTemplate` (тот же, что у Secretary/UI developer/HR): разница
между этими четырьмя профилями физически меньше, чем между QA и Backend
developer — у них общий SOUL.md слово-в-слово (заводской текст Hermes,
неотредактированный под роль) и почти идентичный `config.yaml`. Заводить
четвёртую копию разметки под четыре карточки без содержательной разницы значило
бы плодить дублирование без пользы.

Что по-настоящему разное — вынесено в поля:

- **System Prompt** — реальный `description` из `profile.yaml` каждого профиля
  (единственное, что различается между ними содержательно) плюс число
  реальных сессий в `sessions/` на момент написания.
- Остальные панели (Soul, Thinking, Tools, Permissions, Model, Skills, Agents,
  Memory) — общий текст `HERMES_*`, потому что в файлах и правда нет ролевой
  специфики: `config.yaml` идентичен, `skills/` — тот же bundled-набор,
  `memories/` пусты у всех четырёх. Честно показывать одинаковый текст лучше,
  чем сочинять несуществующие различия.

Иконка 📄 у каждой панели ведёт на настоящий файл в `hermes-home/profiles/<имя>/`
(`applyPanelFiles` в `flow.js`, карта `FILE_BY_ROOT`) — не на файл-заготовку в
`PROJECTS/Flow/profiles/`, потому что для этих четырёх профилей заготовок нет и
не нужно: у них уже есть настоящие файлы на диске.

MCP-панель этих карточек пуста (`HERMES_MCPS = []`) — в `config.yaml` реально
ничего не сконфигурировано, это не недоделанная функция, а точное отражение
текущих настроек.

## Последствия

- Пятый такой профиль (если Hermes-стек заведёт ещё один каталог в
  `hermes-home/profiles/`) добавляется без новой разметки: запись в
  `PERSONAL_ROOTS`/`PROFILE_META`/`ROOT_FIELDS`/`MCP_BY_ROOT`/`FILE_BY_ROOT` в
  `flow.js` плюс строка в `AGENT_ICONS` и список меню — и всё, `SYSTEM/index.html`
  трогать не нужно.
- Если позже профили разъедутся по-настоящему (разный `config.yaml`, ролевой
  `SOUL.md`), поля обновляются на месте — общий `HERMES_*` не обязывает их
  оставаться одинаковыми вечно, это снимок текущего состояния файлов.
- Реальный запуск хода через `hermes -p <profile>` по-прежнему не реализован —
  карточки только показывают состояние файлов, ни к чему не подключены.

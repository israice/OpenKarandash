# 009. Хуки регистрируются по абсолютному пути

## Проблема

В `.claude/settings.json` хуки были прописаны относительным путём — `node .claude/hooks/no-bg-server.js`.
Claude Code запускает хук не обязательно из корня проекта: когда сессию поднимает сервер
через `wsl.exe bash -lc`, рабочим каталогом оболочки оказывается не путь проекта.
Node тогда не находит файл и падает:

```
PreToolUse:Bash hook error
Failed with non-blocking status code: node:internal/modules/cjs/loader:1386
```

Ошибка «не блокирующая», поэтому инструмент всё равно выполнялся — но защита
(`no-bg-server`, `file-lock`, `syntax-check`) при этом молча не работала, а лента сессии
забивалась красными строками, по четыре на каждый вызов Bash.

## Решение

Команда хука пишется от переменной, которую подставляет сам CLI:

```json
"command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/no-bg-server.js\""
```

Кавычки обязательны: путь Windows-хоста содержит пробелы не всегда, но путь проекта
может переехать. Новый хук добавляется в том же виде — относительных путей в
`settings.json` быть не должно.

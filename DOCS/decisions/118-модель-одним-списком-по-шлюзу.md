# Модель выбирается одним списком — те, что есть у выбранного шлюза

Стандарт: **WCAG 2.2, SC 3.3.2 (Labels or Instructions) и SC 4.1.2 (Name, Role,
Value)** — частично. Пункт в списке выбора это подпись значения, и подпись
обязана быть верной: значение, которого у выбранного шлюза нет, вводит в
заблуждение ровно так же, как неверная подпись поля. Само требование «список
предлагает только существующие значения» прямо в WCAG не выражено — это решение
интерфейса, и ниже оно названо исключением с ценой.

## Решение

Уровня Provider в строке выбора больше нет. Строка в шапке сессии — четыре
уровня: **CLI / Gateway / Model / Effort** (`SYSTEM/model-cascade.js`).
Список Model — это каталог моделей выбранного CLI, сужённый до выбранного
шлюза, и ничего кроме него. Значение пункта — путь целиком, каким его понимает
CLI (`openrouter/stealth/space-bunny-alpha`), подпись — тот же путь без головы
(`stealth/space-bunny-alpha`), а у CLI без среднего уровня (pi:
`anthropic/claude-fable-5`) — просто имя модели.

## Почему

Поставщик — не то, что выбирают. Это средний уровень пути модели, и он живёт
разными способами у разных шлюзов: у `openrouter` их несколько, у `anthropic` их
нет вовсе, у `pi` каталог вообще двух уровней. Отдельный список рядом со
списком моделей показывал уровень, которого под частью шлюзов не существует, а
пара «Provider / Model» не была ни одной настоящей моделью шлюза: выбрать
нельзя было ничего, кроме настоящей модели, и выбор разъезжался на две строки.

Разделение вредило и обратной стороне: список Provider сужался по шлюзу, а
значение, выбранное ранее, возвращалось в строку пунктом (`keepAbsent`), то есть
под выбранным шлюзом показывался поставщик, которого под ним нет. Один список
моделей шлюза такой пары не создаёт вовсе — там нет уровня, который можно
показать чужой.

Подпись пункта — путь без головы, а не одно имя модели: у разных поставщиков
имена совпадают, а для CLI это разные модели. Склеивать их в одно значение
нельзя, показывать одинаковыми — тоже.

## Что стало с сохранённым выбором

Уровни выбора (`SYSTEM/providers.js`, ключ `noname.levels`) по-прежнему хранят
шлюз, поставщика и имя модели, и разбираются они из пути выбранной модели.
Поставщика в строке нет, но он хранится: пока каталог CLI пуст (CLI не
подключён), список моделей строится склейкой из уровней (`modelPath`), и без
среднего уровня путь не собрать.

Модель уходит в ход ровно тем значением, которое стоит в уровне Model, и
уровни разбираются из него же — так сохранённое совпадает с показанным. Раньше
уровни сохранялись из пути, склеенного заново по форме каталога, и у CLI, чьё
имя есть среди его же моделей (`opencode/…`, `kilo/…`), получался другой путь:
шлюз из него выпадал, и подпись над ответом теряла его.

## Цена

- Человек больше не выбирает поставщика отдельно. Раньше он мог сузить список
  моделей до одного поставщика, не выбирая модель; теперь тот же список
  получается выбором нужной модели из списка шлюза. Если у шлюза много
  поставщиков, список длиннее — это цена одного списка.
- Старый сохранённый выбор переживает правку: уровни лежат в `localStorage` под
  прежними ключами и читаются как есть, а список Model показывает то, что
  каталог называет под выбранным шлюзом.

## Проверено

Живой прогон на сервере владельца с настоящим каталогом `opencode`
(153 модели, подключение через `/api/agent/connect`): в строке четыре уровня,
Gateway перечисляет настоящие шлюзы каталога, Model под выбранным шлюзу
перечисляет его модели путями, `getActiveModel()` отдаёт тот же путь, который
показан в строке.

# Модалка Settings и окно выбора CLI переехали в шаблон

## Решение

`PROJECTS/Settings/settings-markup.js` удалён: два модальных окна (`#pickerModal`, `#settingsModal`) отдаются шаблоном `PROJECTS/Settings/settings-modal.eta`. Сервер подставляет его в страницу на месте заглушки `{{SETTINGS_MODAL}}` (`renderPage` в `SYSTEM/core/version.js`) и отвечает `/api/fragment/settings-modal` (`PROJECTS/Settings/settings-server.js`). `settings.js` ищет оба модала по id в готовом DOM — вставки больше нет. Горячая перезагрузка `settings.js` снимает только свои слушатели: модалы серверные, их трогать нельзя.

## Почему

Очередь «компонент = шаблон + маршрут + один id» из целевой архитектуры п. 3: последний кусок клиентской вёрстки, который находят потребители при сборке страницы.

## Чем платим

- Если шаблон не дошёл — модаль не найдётся, `settings.js` сразу выходит (вставлял молчание).
- Клиент не сможет «перерисовать» модалки точечно — только полная перезагрузка при правке .eta.
- Сервер должен вернуть это через renderPage, что делает его единственным держателем места модалок на странице.

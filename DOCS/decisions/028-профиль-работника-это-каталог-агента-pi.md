# Профиль работника — это настоящий каталог агента pi

**Решение.** У каждого работника канваса Flow своя папка `PROJECTS/Flow/profiles/<Работник>/`, и это не описание для человека, а каталог агента pi: тот самый, что pi по умолчанию держит в `~/.pi/agent`, а по переменной `PI_CODING_AGENT_DIR` — где укажут (`docs/environment-variables.md`). Первым заведён `profiles/QA/`: `settings.json` (провайдер, модель, `defaultThinkingLevel`, `defaultTools`, `defaultProjectTrust`, список пакетов), `SYSTEM.md` (заменяет системный промпт), `APPEND_SYSTEM.md` (дописывается к нему), `mcp.json` (его читает пакет `pi-mcp-adapter`), `extensions/permission-gate.ts` (подхватывается сам из `extensions/`). Иконка 📄 у заголовка каждой панели ноды QA ведёт теперь в этот файл, а не в пересказ рядом с кодом: прежние `PROJECTS/Flow/{MCP,SOUL,SYSTEM,THINKING,TOOLS,PERMISSIONS}.md` удалены, их содержание переехало в файлы профиля и его `README.md`.

**Почему папка, а не общие настройки.** Работников на канвасе несколько, и различаются они ровно тем, что у pi лежит в каталоге агента: промптом, моделью, уровнем рассуждения, набором инструментов, MCP-серверами, расширениями. Развести их внутри одного `~/.pi/agent` нечем — там по одному экземпляру каждого файла. Зато сам каталог переносится целиком одной переменной, поэтому «профиль работника» и «каталог агента» — это одно и то же, и второй сущности заводить не нужно.

**Почему панель Permissions выглядит именно так.** У pi нет ни режимов разрешений, ни окон подтверждения, ни песочницы (`docs/security.md`, `docs/usage.md`): границы задаются четырьмя рычагами — списком инструментов (`defaultTools`, флаги `--tools`/`--exclude-tools`/`--no-builtin-tools`/`--no-tools`), составом сессии (`-e`, `--no-extensions`, `--no-skills`, `--no-context-files`), доверием проекту (`defaultProjectTrust`, `-a`) и внешней изоляцией (Gondolin, Docker, OpenShell). Поля панели названы по ним, а не по привычной модели Claude Code «файлы / shell / сеть»: сети как рычага у pi нет вообще, а единственная граница внутри процесса — расширение, возвращающее `{ block: true, reason }` на `tool_call`. Тестировщику в `defaultTools` не выданы `write` и `edit`: QA читает и запускает, но не правит.

**Что из этого ещё не подключено.** `askPi` в `server.js` переменную `PI_CODING_AGENT_DIR` не выставляет — ходы по-прежнему идут на общем `~/.pi/agent`, и профиль применяется только при ручном запуске (`PI_CODING_AGENT_DIR=PROJECTS/Flow/profiles/QA pi …`). Когда будем подключать, помнить о двух вещах: ключ провайдера сервер пишет в `~/.pi/agent/auth.json` (`savePiOpenRouterKey`), а pi со своим каталогом будет искать `auth.json` в папке профиля; и `defaultProjectTrust` в профиле стоит `"always"`, потому что в неинтерактивных режимах (`-p --mode json`) диалога доверия нет и при дефолтном `"ask"` проектные `.pi`-ресурсы молча игнорируются. Поля панелей в файлы профиля тоже пока не пишутся — их правят руками через ту же иконку 📄.

**Чем платим.** Файлы, которые pi заводит в каталоге сам (`auth.json`, `sessions/`, `npm/`, `git/`), появятся внутри репозитория — они внесены в `.gitignore`, но папка профиля перестала быть только текстом. И профиль теперь можно сломать опечаткой в JSON: `settings.json` с битым синтаксисом pi не подхватит.

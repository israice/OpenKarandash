# Браузер агента — jev-ultrafast, клон в корне проекта

## Решение

Для управления браузером берём `browser-use/jev-ultrafast`. Код клонируется в `jev-ultrafast/` в корне проекта по образцу `hermes/`: в git его нет (`.gitignore`), карта проекта его обходит (`SYSTEM/core/scan.js`). В git живёт только наша обвязка — `PROJECTS/Browser/`.

## Почему

Инструмент на Python (`uv`), а зависимости проекта — npm, и записка 004 разрешает только те, что убирают существенный объём своего кода. Свой драйвер браузера с выбором элементов писать дороже. Класть его в `package.json` нельзя, а чужой код в наш git — незачем: клон обновляется сам. Ключ TypeSafe у проекта уже есть (`SYSTEM/core/typesafe.js`).

## Чем платим

Ещё один клон с внешним обновлением и второй рантайм (Python и `uv`). Нужен ключ OpenRouter (`TEXT_MODEL_API_KEY`) — в `.env` его пока нет. Chrome стоит на Windows, а Hermes в контейнере, поэтому нужен мост `PROJECTS/Browser/chrome-bridge.js`: прокси на стороне Windows, который сам поднимает Chrome на отдельном профиле и пускает контейнер только по секретному префиксу пути (токен в `.env`). Порт отладки Chrome — полный контроль над браузером и входами в аккаунты, поэтому голым его наружу не выставляем. Мост запускается руками, сторож его не поднимает; отдельный профиль `DATA/chrome-profile` значит, что входить в аккаунты в нём придётся один раз.

## Что проверено

Пакет ставится, импортируется, 31 офлайн-тест проходит. Мост проверен на подставном Chrome (другие порты, токен через окружение): ответ `/json/version` через токен возвращает адрес websocket, переписанный на мост; Chrome получает Host `127.0.0.1`; чужой токен и путь без токена дают 404, в том числе для websocket; websocket доходит до Chrome без Origin, байты идут в обе стороны. С настоящим Chrome на Windows, брандмауэром и платными вызовами не проверялось.

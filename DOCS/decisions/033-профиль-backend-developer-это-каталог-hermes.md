# Профиль Backend developer — настоящий каталог Hermes, не pi

**Решение.** У Backend developer на канвасе Flow теперь своя личная нода
(как у QA — `PERSONAL_ROOTS` в `flow.js`, `#flowNodeBackendTemplate` в
`index.html`, `.flow-node--backend` в `flow.css`), но профиль под ней —
`PROJECTS/Flow/profiles/Backend developer/` — устроен не как каталог агента
pi (`DOCS/decisions/028`), а как настоящий профиль Hermes: `config.yaml`
(`model`, `agent`, `terminal`, `compression`, `display`, `approvals`,
`memory`, `security`, `delegation`, `checkpoints`, `toolsets`, `mcp`),
`SOUL.md` (единственный файл-эквивалент системного промпта — в отличие от
pi, у Hermes нет разделения на «заменить» и «дописать»), `skills/` и
`memories/` (заготовки — `README.md` внутри каждой, реальных файлов пока
нет). Соответствие панелей ноды файлам — в `PROJECTS/Flow/profiles/Backend
developer/README.md`.

**Почему две формы профиля сразу.** Hermes в проекте уже поднят в Docker
через claude-bridge (`DOCS/decisions/029`) — значит для *нового* работника
естественно завести его профиль в форме, которую реально читает Hermes, а
не копировать форму pi, которая для Hermes ничего не значит. QA при этом
**не переведён** на эту форму в рамках данного изменения: его профиль
остаётся каталогом pi как был, и его карточка продолжает работать как
раньше — смешивать в одном изменении миграцию QA с добавлением Backend
означало бы тронуть работающую карточку без необходимости.

**Почему System Prompt и Soul смотрят в один файл.** У pi «заменяющий»
`SYSTEM.md` и «дописываемый» `APPEND_SYSTEM.md` — разные файлы, поэтому у
QA два файла под две панели. У Hermes такого разделения нет: `SOUL.md` —
единственный файл-эквивалент системного промпта. Обе панели карточки
Backend developer (**System Prompt** и **Soul**) ведут иконкой 📄 в один и
тот же `SOUL.md` — две панели, один настоящий файл.

**Почему у Thinking нет иконки файла.** У pi `defaultThinkingLevel` —
отдельное поле `settings.json`. Прямого эквивалента в конфиге Hermes нет:
глубина рассуждения ближе к выбору модели/провайдера
(`config.yaml` → `model`/`agent`), чем к отдельной настройке. Панель
**Thinking** карточки Backend developer поэтому, как и панели Skills/
Agents/Memory у QA, остаётся только текстом — без иконки в файл, которого
для этого понятия по-честному не существует.

**Что из этого не подключено.** `askHermes` в `server.js` профиль пока не
принимает: реальные ходы идут на том Hermes-таргете, что у сервера
настроен по умолчанию, а не через `-p`/конфиг конкретного профиля —
`config.yaml` этого профиля применяется только при ручном запуске.
Тот же самый разрыв решение 028 документировало для pi и `askPi`
(`PI_CODING_AGENT_DIR` там тоже не выставляется) — здесь тот же паттерн:
реальная маршрутизация по профилю остаётся будущим шагом, а не тем, что
сделано сейчас. Поля панелей карточки в файлы профиля тоже не пишутся —
только правка вручную через иконку 📄, как и у QA.

**Чем платим.** Список MCP-серверов в `config.yaml` (`mcp.servers`)
назван по правдоподобным именам npm-пакетов, но не все из них проверены
как реально существующие — в отличие от `mcp.json` QA, где стоит
настоящий, установленный `@playwright/mcp`. Это стартовая форма, которую
нужно будет поправить, когда профиль реально подключат. Отдельного
`.gitignore` внутри папки профиля тоже нет: как и у QA, конвенция проекта
— ловить runtime-файлы профиля общими glob-строками в корневом
`.gitignore` (`/PROJECTS/Flow/profiles/*/...`), а не заводить файл в
каждой папке профиля отдельно; этим изменением в корневой `.gitignore`
добавлена ещё одна такая строка — `.env`, характерный для Hermes секрет,
которого не было в списке pi-профилей.

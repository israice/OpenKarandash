# 116. npm-шим может указывать на нативный бинарник

**Основание:** жалоба владельца 2026-10-07 — карандаш показал, что список Gateway
в каскаде выбора модели пуст и заблокирован. Оказалось: выбранный CLI `opencode`
не подключался вовсе, и списка моделей у него не было.

## Причина

`resolveCommand` (`SYSTEM/cli/any.js`) на Windows ищет `.exe` в PATH, а если его
нет — разбирает npm-шим и запускает найденный вход через node. У opencode
входа-`.exe` в PATH нет (только шимы `opencode` и `opencode.cmd`), а шим
указывает на `…\node_modules\opencode-ai\bin\opencode.exe` — нативный бинарник.

Замер:

| запуск | результат |
|---|---|
| `node.exe …\opencode.exe --version` | `SyntaxError: Invalid or unexpected token` |
| `…\opencode.exe --version` | `1.18.35` |

Дальше цепочка была молчаливой: `detectInstalls` отбрасывает неудачные проверки
(`checks.filter(fulfilled)`), цель терялась, `ensureConnected` возвращал `null`,
`provider.models` оставался пустым, `modelsFor` возвращал пустой список,
`levelValues` давал пустой Gateway, а `fillLevel` вешал на него `disabled`.
Человек видел пустые заблокированные списки без единого слова о причине.

## Что сделано

Вход, который сам исполняемый (`.exe`, `.com`), запускается как есть; на node
он идёт только когда это JS-файл. Правило в коде, подробность здесь.

## Границы

- Это не «исключение для opencode»: так ломается любой CLI, поставленный npm-ом
  с нативным бинарником внутри пакета (bun-сборки в том числе). Правка в общем
  месте, а не в ветке на одно имя.
- `.cmd` и `.bat` по-прежнему идут через node: node не умеет исполнять их без
  shell, и разбирать их вручную здесь незачем — шим распакован до входа пакета.
- Обходной путь (`OPENCODE_BIN`) не понадобился, но он и не мешает: переменная
  окружения проверяется первой строкой и осталась как есть.

## Проверки

- Тем же коннектором, что у сервера (`create` с пустыми зависимостями — цели и
  версии считает сам): opencode → цель `opencode-local`, версия 1.18.35, 552
  модели (`opencode/big-pickle`, …); Hermes Agent не изменился — цель, версия
  0.21.5, одна модель.
- `node --check`, `npm run check` EXIT=0 (четыре файла длиннее 400 — прежние).
- Живой каскад в браузере — за владельцем (002): нужен перезапуск сервера, модуль
  коннектора в памяти процесса старый.

## Что осталось за рамками

Пустой каскад по-прежнему молчит: CLI не найден — и человек видит только
заблокированные списки. Слово о причине в строке выбора (или в ответе `detect`)
ещё не сделано.

## Альтернативы, которые не выбрали

- Ветка на имя `opencode` в `resolveCommand` — лечит один симптом и оставляет
  класс поломки целиком.
- Ошибка из `detectInstalls` вместо тихого отбрасывания — правильнее сама по
  себе, но меняет контракт маршрута `/api/agent/detect`, а это отдельное
  решение; здесь молчание сохранено, чтобы правка осталась локальной.

# 095. Ход ведёт то слово, которое выбрано в списке CLI

## Решение

Слово из уровня **CLI** в строке выбора над сессией — единственный источник истины
о том, кем пойдёт следующий ход, и оно уходит в CLI буквально тем же словом.
Выбрал `kilo` в списке — ход пошёл через kilo. Уровни **Gateway / Provider /
Model** при этом не сбрасываются: по умолчанию они везде
`openrouter` / `stealth` / `space-bunny-alpha`, а меняет человек их по одному, и
после смены CLI показываются те же значения.

Коннектор на каждый CLI не заводится: список приходит с сайта и меняется. В
проекте один коннектор на всех — `SYSTEM/cli/any.js`, — который работает с любым
именем: разбирает его в команду на этой машине, определяет семейство протокола по
собственной справке CLI и оттуда берёт свои флаги запуска и свой разбор потока.

| Что | Стало |
|---|---|
| `SYSTEM/cli/pi.js` | убран; вместо него `any.js` (коннектор) и `any-parse.js` (разбор потока) |
| `CONNECTORS` в `SYSTEM/cli/index.js` | таблица созданных коннекторов по имени CLI; `byName` заводит по требованию |
| `PROVIDERS` | дефолтные записи; запись на любое имя заводится по требованию, в список попадает при подключении |
| `STORE_KEYS`, `MODEL_KEYS` | ключ выводится из имени CLI тем же слагом, что и id цели |
| уровни Gateway/Provider/Model | один ключ `noname.levels` на всех, по умолчанию дефолт проекта |
| строка выбора в шапке | видна всегда, пока виден список сессий, а не только при подключённом провайдере |
| подключение | часть отправки хода (`ensureConnected`), а не отдельная забота человека |

## Почему так

Слово из списка молча игнорировалось, и это была не одна поломка, а три, и все
три выглядели одинаково — «выбрал, а ничего не изменилось»:

- **Выбор отбрасывался.** `getActiveProviderId` отвергал слово, у которого нет
  «своего коннектора», и отдавал провайдера по умолчанию. Ход уходил не туда, куда
  показывала строка выбора.
- **Молчание на уровне выбора.** Пустая модель не доходила до объявления вовсе:
  список моделей у неподключённого CLI пуст, а выбор CLI от него не зависит.
- **Подключение было отдельной задачей.** Выбрать было нечего, пока не нажат
  Connect в настройках, а список CLI тем временем менялся.

## Уровни каскада: почему один ключ на всех

Уровни помнятся по отдельности от склеенной строки модели и под **одним** ключом
на все CLI. Оба решения проверяемы:

- Хранить только строку модели нельзя: смена одного уровня затирала бы остальные,
  и переключение CLI возвращало бы половину пути.
- Хранить свой ключ на каждый CLI тоже нельзя: тогда у kilo был бы свой шлюз, у
  omp свой, и переключил CLI — получил другие значения. А человек переключает
  CLI именно чтобы тем же путём пойти в другом.

Поэтому уровни общие, дефолт один, а каталог CLI (когда он есть) только сужает
список уровней. Значение, которого в каталоге нет, в строку возвращается пунктом
обратно (`keepAbsent`): каталог не решает, что выбрал человек.

Модель у разных CLI называется по-разному, и это нормально: у pi и omp путь
начинается с `openrouter`, у kilo — с `kilo`. Каскад показывает то, что уйдёт в
CLI, а подпись ответа (`SYSTEM/model-tag.js`) не повторяет имя CLI, когда путь
модели сам с него начинается.

## Один коннектор на всех

`any.js` узнаёт CLI в три шага, и все три шага нужны потому, что список имён
приходит извне:

1. **Имя → команда.** «Kilo Code» — это `kilo`, «Claude Code» — `claude`,
   «Hermes Agent» — `hermes`: пробуем слитно и по словам. Дальше PATH, а на
   Windows npm-шим раскрывается до входа пакета на node — тот же приём, что был
   в коннекторе pi, только теперь он общий. Переменная окружения
   (`<СЛОГ>_BIN`) перекрывает всё.
2. **Семейство протокола — по собственной справке CLI.** Справка читается и из
   stdout, и из stderr (kilo печатает её туда), а у opencode-схемы ещё и из
   справки подкоманды `run`: свои флаги хода видны только там.
3. **Свои флаги и свой разбор.** Семейства, проверенные живьём на этой машине:
   **pi** (`-p --mode json`, `session` / `tool_execution_*` / `message_end`, список
   `--list-models` или `models list`), **opencode** (`run … --format json
   --thinking`, `text` / `reasoning` / `tool_use` / `step_finish`, список `models`),
   **openclaw** (промпт в файле, каталог с `--all --json`, ответ одним объектом в
   конце — своё лежит в `any-openclaw.js`) и **plain** — всё остальное: ход идёт как
   `run «…»`, ответом считается весь вывод.

Определение семейства кэшируется на цель: спрашивать `--help` на каждом ходе
стоило бы целого запуска процесса.

## Почему список CLI — источник, а не украшение

Слово из списка игнорировалось с трёх сторон сразу, и все три выглядели одинаково:

- `getActiveProviderId` отвергал имя без «своего коннектора» и отдавал провайдера
  по умолчанию — ход уходил не туда, куда показывала строка выбора;
- пустая модель не доходила до объявления вовсе, потому что список моделей у
  неподключённого CLI пуст, а выбор CLI от него не зависит;
- подключение было отдельной задачей, то есть до Connect выбрать было нечего.

Теперь слово уходит в CLI буквально тем же, каким выбрано, и подключение —
часть отправки хода (`ensureConnected`): строка выбора видна всегда, пока виден
список сессий. Если CLI на машине нет, ход говорит об этом тем же именем, а не
уходит молча к другому.

## Чем платим

- Уровни каскада не различаются по CLI. Тот, кто захочет у разных CLI разные
  пути, должен будет ждать отдельного ключа на CLI — но это ровно то расхождение,
  ради которого всё затевалось.
- Строка выбора в шапке Sessions показывает дефолт проекта и у того CLI, чей
  каталог пуст, — уровни не сбрасываются, но список под ними пуст. Это честнее
  прочерков: выбор виден, а каталог CLI приедет при подключении.
- `plain`-семейство отвечает одним блоком: шагов и размышлений такой CLI не
  отдаёт, в ленте будет только текст ответа. Это осознанная граница: разбор
  потока незнакомого CLI без его справки не восстановить.
- Списки моделей у разных CLI приходят в разном виде (таблица, рамка, путь по
  строке, JSON). Разобраны четыре формы; CLI, который печатает пятую, получит пустой
  список и останется на дефолтных уровнях — молча, без ошибки на экране. Так и
  ведёт себя OpenClaw на этой машине: он отвечает, но каталог у него пустой
  (Gateway не запущен, все модели помечены `available: false`) — уровни при этом
  остаются дефолтными, и ход всё равно уходит.

## Что проверено

- Уровни каскада живьём: дефолт `openrouter/stealth/space-bunny-alpha` одинаков у
  всех CLI; смена CLI ничего не сбрасывает; смена Gateway на anthropic оставляет
  Provider и Model прежними; после возврата к pi уровни те же.
- Строка выбора в шапке — источник истины: выбор `Kilo Code` даёт ход через
  `Kilo Code`, и перерисовка строки этот выбор удерживает.
- Найдены и опрошены живьём: `pi` 1.0.2 (434 модели), `Kilo Code` → kilo 7.4.22
  (333 модели), `omp` 18.6.0 (560 моделей), `claude` 2.1.285,
  `Hermes Agent` → hermes 0.21.5, `OpenClaw` 2026.9.8 (каталог пустой — см. выше).
- Через маршруты живого сервера: `/api/agent/detect` и `/api/agent/connect` отвечают
  для `Kilo Code`, `omp` и `OpenClaw`; модели приезжают у первых двух.
- Живой ход через kilo (схема opencode): `sessionID` распознан, событие `text`
  дошло («ок»). Живой ход через pi и omp доходит до провайдера и падает на
  дневном лимите бесплатных моделей OpenRouter (429) — это лимит аккаунта, а не
  коннектора.
- `agentNameByTarget` по целям: `kilocode-local` → Kilo Code, `omp-local` → omp,
  `pi-local` → pi, `opencode-windows` → pi (как и раньше), пусто → pi.
- Подписи моделей: `pi/openrouter/stealth/space-bunny-alpha`,
  `Kilo Code/kilo/stealth/space-bunny-alpha`, `omp/openrouter/anthropic/claude-opus-5-5`.

Интерфейс живьём не проверялся: сервер из сессии не поднимается
(`DOCS/decisions/002`). Живой прогон — за владельцем:
`node TOOLS/live-verify/run.mjs connect-cli agent=kilo`, затем
`node TOOLS/live-verify/run.mjs short-turn`.

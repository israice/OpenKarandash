# 094. Вместо OpenCode в проекте ход ведёт pi

## Решение

Агентом проекта остался один, и теперь это **pi**
(`@earendil-works/pi-coding-agent`), а не OpenCode. Шлюз, поставщик и модель не
поменялись: `openrouter` / `stealth` / `space-bunny-alpha` — те же самые, что
были у OpenCode, и та же строка по умолчанию в `SYSTEM/providers.js`.

Правка сделана как замена одного имени, а не переделка слоя: единственным
источником истины остаётся id провайдера в `PROVIDERS` и `DEFAULT_AGENT`.

| Что | Стало |
|---|---|
| `SYSTEM/cli/pi.js` | коннектор pi вместо `SYSTEM/cli/opencode.js` |
| `DEFAULT_AGENT`, ключ `CONNECTORS` | `pi` |
| `PROVIDERS[0]`, `STORE_KEYS`, `MODEL_KEYS` | `pi` / `noname.pi` / `noname.model.pi` |
| id целей | `pi-windows`, `pi-custom`, `pi-linux` |
| `.env` | `PI_BIN` вместо `OPENCODE_BIN` |
| `PROFILE_BY_AGENT` | `{ pi: 'Backend developer' }` |
| `opencode.json` | убран (см. ниже) |

## Почему так

Пользователь выбрал pi тем же способом, каким раньше выбирал OpenCode: именем в
списке CLI. Менять нужно было ровно это имя — остальное (шлюз, поставщик, модель,
маршруты, таблицы, обвязка хода) у агентов общее, и трогать его было незачем.

Коннектор написан заново, но по контракту, который в проекте один на все CLI
(`DOCS/decisions/017`): своя цель запуска, свой detect, свой разбор потока. Ход
идёт через `-p --mode json`, как в прошлый раз, когда pi ещё был в проекте.

Три отличия от прежнего коннектора pi, и все три — по факту проверки:

- **Windows.** У pi нет бинарника, который можно запустить: `where pi` находит
  npm-шимы, а spawn без shell их не берёт. Ищем вход пакета
  (`@earendil-works/pi-coding-agent/dist/bundle/cli.js`) рядом с шимом и
  запускаем тем же node, на котором работает сервер. Если входа нет — цели
  нет в списке вовсе, а не «найдена и падает».
- **Список моделей.** `pi --list-models` печатает таблицу с колонками, а не
  плоский список строк: колонки разбираются по двум и более пробелам и
  склеиваются обратно в `provider/model` — ровно в том виде, какой потом
  принимает `--model`.
- **Chat-режим стал настоящим.** У pi нет `--permission-mode`, зато есть
  `--tools`: в режиме Chat ход получает только читающие инструменты
  (`read, grep, find, ls`). Ограничение теперь держит CLI, а не формулировка
  вопроса.

Профиль памяти привязан к `Backend developer` (его `config.yaml` и так называет
`openrouter` и `space-bunny-alpha`). Каталог `QA` остался в проекте, но к агенту,
который ведёт ход, отношения не имеет — он достался в наследство от прежнего
коннектора pi.

`opencode.json` убран по правилу решения `078`: конфиг CLI, которого в проекте
нет, читается как рабочая настройка, а на деле никто его не читает. Правила
проекта pi читает сам — `AGENTS.override.md` попадает ему как контекстный файл
(проверено живьём, в системном промпте виден `project_instructions`), отдельный
`pi.json` не нужен.

Уровень CLI в каскаде перечисляет ровно список с сайта OpenRouter
(`SYSTEM/cli-agents.js`) и ничего кроме него, кроме отключённого пункта Add:
наши собственные провайдеры в этот список не подмешиваются, попасть в него
можно только через Add. Так список остаётся перечнем того, что есть у
OpenRouter, а не смесью этого перечня с тем, что уже настроено в проекте.
Настоящим пункт узнаётся по совпадению имени с id провайдера, а не по тому,
что его передали в строку, поэтому `pi` остаётся настоящим и в шапке сессии, и в
витрине, и когда подключён он один.

## Что пришлось сохранить отдельно

Сохранённое подключение лежит в `localStorage` под ключом по имени агента, и
после смены имени оно стало невидимым: провайдер читался как неподключённый, а
строка выбора в шапке Sessions пропала до нажатия Connect (она рисуется только
при подключённом провайдере, `renderSessionBarControls` в `SYSTEM/model-cascade.js`).
Поэтому в `loadPiState` один раз читается старый ключ и сразу забывается.
Пришедший с ним id окружения чужой (`opencode-windows`), но это не мешает:
`/api/agent/connect` принимает единственную найденную цель вместо сохранённого
имени и возвращает серверу её настоящий id.

## Чем платим

- Старые сессии с `target` вида `opencode-*` теперь приписываются
  `DEFAULT_AGENT` — то есть pi (`agentNameByTarget`). Их история читается целиком,
  но продолжить такую сессию сможет только pi, и пересказ истории придёт
  преамбулой, а не продолжением собственной сессии CLI.
- Модель, выбранная у человека, больше не подменяется: у OpenCode не было
  флагов ограничения инструментов, у pi в режиме Action их тоже нет — разница
  только в Chat, где ограничение настоящее.
- Инструменты замеров (`TOOLS/steps/`) и сценарии `live-verify` смотрят на
  сессии по префиксу `pi-`: накопленная история замеров под старым префиксом
  в новые сводки не попадает.

## Что проверено

- `pi --list-models` отдаёт `openrouter  stealth/space-bunny-alpha`, и модель из
  `DEFAULT_AGENT_MODEL` в списке CLI есть — 434 модели.
- Живой ход настоящей формой аргументов (`-p --mode json --model … --tools
  read,grep,find,ls -- <промпт>`): заголовок сессии с id, `message_end` с
  `provider: openrouter`, `model: stealth/space-bunny-alpha`, usage и текст ответа.
- Коннектор без сервера: `targets()` находит `pi-windows`, `detect()` отвечает
  `1.0.2`, `models()` отдаёт 434 модели с дефолтной в списке.
- `AGENTS.override.md` виден pi как `project_instructions` в системном промпте.

Интерфейс живьём не проверялся: сервер из сессии не поднимается
(`DOCS/decisions/002`). Живой прогон — за владельцем:
`node TOOLS/live-verify/run.mjs connect-cli agent=pi`, затем
`node TOOLS/live-verify/run.mjs short-turn`.

# Поиск модели и Node.js в рабочих столах

## Проблема

Нативный список `<select>` не позволяет добавить строку поиска внутрь раскрытого
меню, а общий образ Linux-рабочего стола не содержал Node.js/npm. Из-за этого
длинный каталог моделей было неудобно искать, а новый рабочий стол не мог
запускать Node-проекты и их проверки до отдельной установки рантайма.

## Решение

- Для уровня Model оставить существующий `<select>` источником значений и
  событий, но открывать поверх него доступное поисковое меню со списком его
  актуальных `option`. Фильтрация не меняет выбор; выбор пункта синхронно
  обновляет исходный селект и отправляет обычное событие `change`.
- В общий Linux-образ рабочих столов добавить Node.js 22 и npm, взятые из
  официального образа `node:22-bookworm`, чтобы совпадать с версией Node
  приложения.
- На Linux считать завершившиеся zombie-процессы мёртвыми в проверке замка, а
  тесту разрешить результат `not-running`, когда сторож сам снял замок.
- Не переносить dev-зависимости проверки в производственный образ приложения:
  отдельные рабочие столы устанавливают зависимости проекта через `npm ci`.

## Последствия и ограничения

Меню поиска работает только для уровня Model; остальные уровни сохраняют
нативное поведение. Существующие слушатели и сохранение выбора продолжают
работать через исходный `<select>`. Новые рабочие столы получают Node/npm после
пересборки общего образа; уже созданные контейнеры образ не меняют. Linux
считает zombie-процесс завершённым, хотя `kill(pid, 0)` ещё подтверждает его PID.

# Ход не собрался — значит чат пуст: сборка аргументов CLI проверяется машинно

**Решение.** В `npm run check` (`SYSTEM/checks.js`) добавлена стадия «аргументы
хода CLI» — скрипт `SYSTEM/cli-args-check.js`. Она проверяет одно: коннектор
CLI умеет собрать аргументы хода для каждого семейства (`opencode`, `pi`,
`plain`), и в CLI уходят выбранная модель и её родные флаги.

Настоящий CLI проверка не запускает: подменены и его справка (по ней
опознаётся семейство), и сам запуск (`SYSTEM/cli/spawn.js`). Ход стоит минут и
денег, а проверка должна быть быстрой и повторяемой. Идёт она через публичный
контракт коннектора (`create` → `activate` → `ask`), поэтому внутренности трогать
не нужно: сломается путь внутри — упадёт проверка.

Правка дефекта — `SYSTEM/cli/any.js`: вызов `families.get(target)` заменён на
`launchFlags(target)`, тот же доступ к данным семейства, который рядом уже
используется.

**Почему.** 2026-10-22 жалоба владельца: «чат в проекте не исправен, не удалось
создать диалог с новой сессией, выдает ошибку families.get is not a function».
Ошибка пришла из v0.0.191: семейство CLI уехало из `any.js` в отдельный файл
`SYSTEM/cli/any-family.js`, где кэш лежит за `create()` и отдаётся через `of()`
и `flags()`. Три вызова переписали, а один — `families.get(target)?.variants` в
`buildArgs` — остался: `families` стал объектом `{ capture, of, flags }`, и
`get` у него нет. Любой ход семейства `opencode` падал до запуска CLI, и
человек видел в чате ошибку вместо ответа.

Проверок, которые бы это увидели, не было:

- `node --check` видит только синтаксис;
- `eslint` с единственным правилом `no-undef` не знает, какие методы у
  полученного объекта есть: неизвестное имя — другое;
- `madge --circular server.js` смотрит связи модулей, а не форму объекта;
- `SYSTEM/esm-links.js` (записка 123) обходит браузерные ES-модули; серверный
  CommonJS он не обходит, и в CommonJS такой вызов — не ошибка связывания, а
  TypeError в рантайме.

Проверка добавлена после того, как сначала прогнана на живом материале: на
сломанном дереве она назвала ровно тот дефект, который был (`opencode: ход не
собрался — families.get is not a function`), на заклеенном — чисто. Порог
поставлен только после этого: красная всегда проверка учит обходить себя
(записка 034).

**Чем платим.** Стадия печатает находки списком, проходит по дереву за доли
секунды и настоящего CLI не трогает.

**Что не менялось.** Поведение хода прежнее: `--variant` уезжает по-прежнему
только тем значением, которое эта модель знает (у нового opencode флага
`--variant` нет, и уровень Effort на что-то не влияет — это отдельная правка,
названная в записке 126). Семейства `openclaw` и `hermes` собирают аргументы в
своих файлах, и проверка их не покрывает.

**Проверено.**

- стадия на живом материале: до правки назвала дефект (`opencode: ход не
  собрался — families.get is not a function`), после правки — чисто;
- живой сервер владельца: `/api/agent/connect` (opencode 2.0.32, 167 моделей) и
  настоящий ход через `TOOLS/live-verify` (`short-turn agent=opencode
  model=opencode/beam-free`) — события `session`/`thinking`/`text`/`done`, ответ
  «ок.», строки базы совпали с живыми событиями (`user` 1, `thinking` 1,
  `assistant` 1), пропусков нет, EXIT=0;
- `npm run check` EXIT=0.

**Не проверено.** Семейства `openclaw` и `hermes`. Живой браузер владельца
(002) — ход проверен через API и сценарий `live-verify`, а не глазами в чате.

**Связано:** [123](123-связи-браузерных-модулей-проверяются.md) — такой же
случай для браузерных модулей, [034](034-проверки-перед-готово.md) — почему
новая стадия сначала прогоняется на живом материале, а потом становится
порогом, [126](126-каскад-выбора-наполняется.md) — оттуда пришло семейство CLI.

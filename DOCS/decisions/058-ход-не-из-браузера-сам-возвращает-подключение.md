# Ход не из браузера сам возвращает подключение агента

## Решение

Ход, начатый не из браузера (ответ человека в Telegram, голос в опросе), перед запуском сам возвращает подключение тому CLI, который вёл сессию: находит окружение по `target` сессии, запускает версию CLI и активирует его — тем же путём, что `/api/agent/connect`. Не вышло — работу берёт любой подключённый агент, контекст он получает пересказом (`handoffPreamble`), модель и effort прежнего ему не передаются. О замене человеку уходит письмо: «pi недоступен — работу продолжит claude». Нет ни одного подключённого — отказ, как раньше.

## Почему

Подключение CLI живёт в памяти процесса, а сторож перезапускает сервер на каждой правке серверного файла. Сам сервер при старте подключает только claude; остальных возвращает страница пульта, когда она открыта. У хода из Telegram страницы нет. 2026-09-21 владелец проголосовал в опросе через две минуты после перезапуска и получил «pi is not connected — open Settings and connect it», хотя pi стоял на месте; опрос при этом закрылся, и ответ пропал.

Замена агента — не тихая: сессия на бесплатной модели может уехать на платную, и владелец обязан это видеть.

## Чем платим

Первый ход после перезапуска дольше на запуск версии CLI (секунды). Запасной агент выбирается первым подключённым по порядку таблицы `AGENTS` — без учёта цены; если это станет важно, порядок задаётся там же.

## Что проверено

2026-09-21 на сервере владельца: после перезапуска подключён был только claude; владелец дописал в опрос свой вариант — ход выполнил pi той же бесплатной моделью и создал файл по ответу. Ветка с запасным агентом живьём не проверялась: для неё нужно сломать CLI.

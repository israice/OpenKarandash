# 111. Метрика сложности: JSON-маршрут и панель Book

**Основание:** п. 5 дорожной карты (`DOCS/целевая-архитектура.md`): «размер файлов, число связей, глубина вложенности — отчёт, который видно в интерфейсе». До этого пункта в roadmap она была записана, но контракта у неё не было: ни записки-решения, ни маршрута, ни UI. Решение по форме зафиксировано владельцем 2026-10-07.

## Что измеряем

Только фактические значения, без оценок и без «умных» индексов:

| Метрика | Как считается | Порог |
|---|---|---|
| Длина файла | строки `.js/.mjs/.cjs`, тот же обход, что у `npm run check` (022) | > 400 строк |
| Число связей | исходящие `require('...')` на файл | топ-10 |
| Глубина вложенности | сегменты пути файла от корня | максимум и топ-10 |

Объём обхода тот же, что у проверок: `node_modules`, `DATA`, `.git`, `.kilo` и т.п. пропускаются.

## Контракт

- Владелец ответственности — `PROJECTS/Graph` (карта проекта уже там): новый модуль `graph-complexity.js`, маршрут `POST /api/complexity` в `graph-server.js`.
- Метод — POST, как у всего остального API, и клиент ходит через `window.App.api`. GET не годится: `SYSTEM/core/api.js` разрешает его только `/api/fragment/*` и `/api/image/*` — тем маршрутам, которые браузер тянет сам, без тела запроса. Попытка сделать этот маршрут GET'ом требовала бы расширить общее правило ради одного потребителя, то есть поменять публичный контракт `api.js`. Обратная правка (`fetch` без `method` в `book-tab.js`) отбивалась 405 `Expected POST` — проверено прямым вызовом `createApi`.
- Ответ — JSON: `{ files, maxLines, longFiles, maxFolderDepth, topRequires, topDepth }`.
- UI — вкладка Book: карточка «Complexity» в списке слева; отчёт показывается в той же правой панели, что и README, read-only (править нечего — это метрика, а не файл).

## Что сознательно не делаем

- Не рисуем граф и не добавляем пороговую раскраску — п. 2 (карта) уже существует как Graph/vault; сложность здесь — числовой отчёт.
- Не считаем циклические связи — их уже ловит madge в `npm run check`.
- Не выводим метрику владельца в автономный «индекс сложности» — до второго потребителя это была бы абстракция на будущее.

## Проверки

- `node --check` на новых/изменённых файлах.
- `POST /api/complexity` на живом сервере владельца отдаёт ожидаемый JSON (длины, топ-связей).
- `npm run check` чисто; живой прогон Book через `npm run ui` + `live-check` — за владельцем (002), так как агенту сервер не поднять.

## Альтернативы, которые не выбрали

- Отдельная `.eta`-вкладка — UI был пустым местом; вкладка с одним отчётом — лишняя точка входа.
- Секция в `npm run check` — не «видно в интерфейсе»: требование п. 5 именно про браузерный UI.

# Связи браузерных модулей проверяются машинно

**Решение.** В `npm run check` (`SYSTEM/checks.js`) добавлена стадия «связи
браузерных модулей» — скрипт `SYSTEM/esm-links.js`. Она проверяет две вещи:

1. каждый именованный импорт браузерного ES-модуля попадает в экспорт файла,
   из которого импортируют (`import { addMessage } from './sessions-feed.js'`);
2. в графе браузерных модулей нет кругов.

Проверка связывает модули тем же линкером, что и браузер (ES-линкер Node), но
без оценки: код модулей не выполняется, DOM не нужен. Пакеты из importmap
страницы (`three`, `@dimforge/...`) подменяются пустыми — их экспортов мы не
берём.

**Почему.** 2026-10-21 вкладка Sessions перестала открываться: не открывалась
и новая сессия, и лента, и список — вкладка просто не грузилась. Причина была
одна и её не видели ни одна из прежних проверок: ленту разложили по файлам
(`sessions-feed.js` → семь модулей), при разложении **потеряли реплику**
(`addMessage`), а её импортировали двое — поток (`sessions-stream.js`) и
история из базы (`sessions-history.js`). В ES-модулях такой импорт не синтаксис
и не неизвестное имя: это ошибка связывания, `SyntaxError: The requested module
'./sessions-feed.js' does not provide an export named 'addMessage'`. Браузер
роняет из-за неё **весь граф** — вкладка не грузится целиком, на экране пусто,
и ошибка видна только в консоли браузера.

Проверок, которые бы это увидели, не было:

- `node --check` видит только синтаксис;
- `eslint` с единственным правилом `no-undef` не знает, что модуль что-то
  экспортирует: неизвестное имя — другое;
- `madge --circular server.js` обходит граф сервера, а браузерные модули
  (`PROJECTS/`, `SYSTEM/*.js`) сервер не грузит — круги в них он тоже не видел.

Проверка добавлена после того, как сначала прогнана на живом материале: на
сломанной копии дерева она назвала ровно тот дефект, который был
(`sessions-stream.js` и `sessions-history.js` — импорт `addMessage`), и на
заклеенном дереве — чисто.

**Чем платим.** Стадия требует `--experimental-vm-modules` (`vm.SourceTextModule`
за этим флагом) — скрипт перезапускает себя с ним сам, предупреждение Node о
экспериментальном API гасится точечно. Проверка проходит по всему дереву за
несколько секунд и печатает находки списком с именем файла и имёнем. Порог
поставлен только после того, как стадия дала чистый результат на живом
материале: красная всегда проверка учит обходить себя (записка 034).

**Что нашла сразу.** Кроме потерянной реплики — два сломанных импорта в
песочных часах (`PROJECTS/Settings/settings-sandglass-*.js`, с v0.0.182):
`GRAINS_N` брался из `settings-sandglass-geometry.js`, который его не
экспортирует, и `GRAIN_R` — из `settings-sandglass-constants.js`, который его
не экспортирует. Из-за этого граф песочных часов не связывался вовсе. Оба
импорта поправлены: `GRAINS_N` приходит из constants, `GRAIN_R` — из geometry,
где он и считается.

**Связано:** [022](022-один-файл-одна-тема.md) — один файл, одна тема, и
поэтому круг между шагом и мыслью недопустим, [034](034-проверки-перед-готово.md) —
почему проверки вообще нужны и почему новая стадия сначала прогоняется на
живом материале, а потом становится порогом.

# 031. Прямая передача задач между специалистами Hermes — без очереди канбана

## Контекст

Пользователь хотел, чтобы вся работа шла по модели «IT-офиса»: один специалист передаёт задачу другому не полным контекстом переписки, а чёткой инструкцией, нужной именно для его части. Первая идея — вести это через доску канбана внутри Hermes (`hermes-home/kanban.db`), чтобы каждая такая передача была видна карточкой.

Проверка показала прямое противоречие с другим требованием пользователя — «никаких задержек, всё в реальном времени»: канбан-доска Hermes по устройству — это очередь с диспетчером, который проверяет её раз в интервал (по умолчанию 60 секунд, конфигурируемо, но не мгновенно), и на каждую карточку поднимается отдельный процесс. Это подтверждено живыми логами: единственная существовавшая задача (`t_a00a9814`) была подхвачена специалистом `qa-checker` с задержкой в минуты после постановки, а не сразу.

## Решение

Передача между специалистами делается синхронным вызовом конкретного профиля Hermes с явной инструкцией — без очереди, без ожидания тика диспетчера, без карточки на доске.

Обёртка: `hermes-home/bin/handoff <профиль> "<инструкция>"`. Она сама подтягивает `CLAUDE_BRIDGE_TOKEN` из `.env`, выставляет `HERMES_HOME` на `hermes-home` этого проекта и вызывает `hermes -p <профиль> -z "<инструкция>"`, возвращая ответ сразу же, как только специалист его дал.

Проверено вживую дважды: профиль `qa-checker` и профиль `docs-writer` — оба ответили корректно и синхронно (12–20 секунд на вызов, без участия очереди канбана и без тика диспетчера).

## Почему не канбан-доска

Два механизма физически несовместимы: мгновенный синхронный ответ и очередь с диспетчером — разные модели по конструкции, а не по недоработке. Канбан-доска Hermes остаётся полезной для другого класса задач — тех, что переживают перезапуск и которым нужна видимая история, — но не для сценария «специалист спросил специалиста и тут же получил ответ».

Дух исходного требования («передавать только то, что нужно для его части работы, а не всю историю разговора») сохранён: вызов `handoff` передаёт ровно инструкцию, а не контекст текущей сессии.

## Профили-специалисты

Используются уже существующие профили Hermes (`developer`, `qa-checker`, `reviewer`, `docs-writer` и т.д., видны в `hermes-home/.local/bin/`); при необходимости более узкой специализации заводятся новые профили тем же способом — без изменений в этом механизме передачи.

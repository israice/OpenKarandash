# Каскад выбора наполняется: семейство CLI больше не теряется на новой справке

## Решение

1. **Семейство протокола CLI узнаётся по usage-строке подкоманды, а не по
   прежнему «run [message]».** `SYSTEM/cli/any-family.js` (было — внутри
   `any.js`): справка подкоманды `run` снимается, когда CLI её упоминает
   (строка `run` в списке команд или `run [` в usage), и opencode-схема
   опознаётся по этой строке вместе с `--format`.

2. **Каталог выбранного CLI берётся при отрисовке строки выбора**, если его
   нет: после перезагрузки страницы в клиенте его нет (в localStorage лежит
   подключение, а список моделей — нет), уровни Gateway и Model стоят пустыми,
   и выбрать из них нечего (`SYSTEM/session-model-bar.js`).

3. **Определение семейства вынесено в отдельный файл** `SYSTEM/cli/any-family.js`
   вместе с чтением вывода CLI (`capture`): `any.js` и так был у нормы в 400
   строк, а правило проекта — «один файл, одна тема» (`DOCS/decisions/022`).

## Почему

Жалоба владельца 2026-10-21: «в проекте выбираю CLI, но не удаётся после
этого выбрать из Gateway и Model».

Проверено на живой странице безголовым Edge (`TOOLS/live-verify`): после смены
CLI уровни были пустыми — Gateway содержал только пустой пункт и «Add», Model —
один пустой пункт. Список моделей у выбранного CLI приходил пустым, а список
моделей и есть то, из чего эти уровни наполняются.

Причина — не в каскаде, а в определении семейства CLI. Клиент opencode
обновился до 2.0.32 и печатает справку иначе:

| | прежняя справка | справка 2.0.32 |
|---|---|---|
| список команд | `run [message..]` | `run — Run OpenCode with a message` |
| usage подкоманды | `kilo run [message..]` | `opencode run [flags] [<message...>]` |

Признак opencode-схемы был `/run \[message/i`, и в новой справке он не
встречается. Что из этого вытекло:

- семейство оставалось `plain` — а это значит ход `run "…"` без `--model` и без
  `--format json`, то есть без потока событий (ответом считался весь вывод
  процесса) и без выбранной модели;
- каталог моделей не брался вовсе: список пуст, и уровни Gateway и Model
  стояли пустыми.

Правка прежнего решения (записка 124) тут ни при чём: она брала каталог сразу
при смене CLI, но каталог приходил пустым.

Проверено на машине: `opencode models` отдаёт 207 моделей (свои бесплатные
`opencode/…` и чужие `aihubmix/…`, `nvidia/…`), а коннектор до правки
возвращал 0.

## Стандарт

Разбор чужого вывода — по фактическому тексту, а не по одному признаку:
формат справки CLI меняется между версиями, и опора на одну строку означает,
что смена версии молча ломает коннектор. Признаков должно быть два, и каждый
проверяем отдельно: usage-строка подкоманды и её флаги.

## Чем платим

- `opencode run --help` снимается лишний раз для CLI, у которых в справке есть
  строка `run` (второй запуск процесса, ~0.1 с, один раз на цель).
- Каталог берётся при каждой отрисовке строки выбора, если его нет: страница
  перезагружается раз в коммит, и каждый раз — запрос каталога у CLI (у opencode
  ~0.5 с, у pi ~4 с, в фоне). Без этого уровни после перезагрузки пусты до
  первого действия человека, а выбрать модель — его цель.
- Уровень Effort при новом opencode ни на что не влияет: у него нет флага
  `--variant` (уровень входит в имя модели как `provider/model#variant`), и
  флаг в ход не уходит. Это отдельная правка, здесь не сделана.

## Что не менялось

- Каскад выбора и его правила — прежние (`SYSTEM/model-cascade.js`): чинилось
  не наполнение, а пустой каталог, из которого оно берётся.
- Смена CLI по-прежнему берёт каталог сразу (записка 124) — эта правка
  оказалась правильной, просто каталог был пуст.
- Семейства pi, openclaw, hermes, kilo и omp не тронуты: у них свои признаки,
  и новый opencode их не пересекает. Проверено на машине: pi — 449 моделей,
  omp — 584, kilo — 334, hermes — 1, opencode — 207 (было 0).

## Проверено

- Живая страница (безголовый Edge, `TOOLS/live-verify`): на свежей странице
  строка выбора наполняется сама (Gateway: opencode, aihubmix, nvidia; Model:
  10 моделей opencode); после смены CLI — то же, каталог нового CLI.
- Пробный ход настоящим opencode с выбранной моделью `opencode/beam-free`:
  поток событий (thinking, text, done), ответ «ок.», строки базы совпали с
  живыми событиями. До правки семейство было `plain` — ход шёл без `--model`
  и без потока.
- `npm run check` EXIT=0; `SYSTEM/cli/any.js` — 357 строк (было 406 после
  правки, норма проекта — 400, `DOCS/decisions/022`).

# Прогон живого интерфейса — одной командой, без Playwright

## Решение

`npm run ui` (`SYSTEM/ui-walk.mjs`) открывает пульт в отдельном безголовом Edge, перезагружает страницу с включённым сбором ошибок и проходит всё подряд: каждую вкладку из `App.VIEWS`, каждую страницу кнопки «+» (кнопки `[data-page]` в тулбаре) и окно настроек. По каждой пишет строку отчёта — сколько видимых элементов и текста, какие ошибки пришли, пока она была открыта (исключения, `console.error`, ошибки загрузки ресурсов). Вкладка без элементов и без текста, непоказанная или ненайденная, как и любая ошибка, — `FAIL` и код выхода 1.

Список вкладок скрипт не хранит: берёт его со страницы. Новая вкладка или страница «+» попадает в прогон сама.

`npm run ui -- --selftest` роняет в странице исключение и проверяет сам сборщик: прогон обязан его показать.

## Почему не ui-checker с Playwright MCP

Так задумывалось (`DOCS/decisions/034`), но сервер отвечает только локальным запросам Windows, а агент работает в WSL: браузер Playwright оттуда получает 403. Тот же обход, что у `SYSTEM/live-check.mjs` — node на стороне Windows и Edge по протоколу отладки, — работает без MCP, без зависимостей и вызывается одной командой; из WSL скрипт сам перезапускает себя через powershell. Сервер по-прежнему поднимает пользователь (`DOCS/decisions/002`).

## Чем платим

Прогон видит, что вкладка открылась непустой и без ошибок, но не знает, правильно ли она нарисована, и не нажимает кнопок внутри вкладок. Сценарии (отправить ход, сверить ленту в трёх отображениях) остаются за `live-check.mjs` и пишутся под задачу.

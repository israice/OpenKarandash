# 132. Поручение без reply заводит новую работу, reply продолжает свою сессию

## Решение

Маршрут приёма лички бота (`telegram-inbox-server.js`) отныне такой. Сообщение с
reply идёт ровно в ту сессию, письма которой оно адресовано, — как и было
(DOCS/decisions/024). Сообщение без reply заводит **новую** работу, раньше оно
наугад уходило в последнюю сессию, о которой этому чату писали. Исключение одно,
два в одном:

- короткий ход вдогонку: пока работа этой лички идёт (её ход занят или сессия
  запущена в пульте), сообщение без reply отвечается в неё же — как прописано в
  062, иначе погоня репликами за ходом заводила бы копию работы на каждую реплику;
- служебные слова («стоп», «что там», «спасибо») ходов не поднимают и работ не
  заводят: «стоп» и «что там» достаются идущей/последней работе («стоп» без
  reply должен останавливать текущую — иначе остановить её с телефона можно
  было бы только реплаем), «спасибо» просто отвечает «👌». Их разбор
  (turn-judgment.js, DOCS/decisions/054) теперь идёт до выбора адресата и для
  reply-сообщений тоже — тот же разбор, тот же порог уверенности.

Флаг «новая работа» от кнопки END (`telegram_chat_state.fresh`) адресатом
сообщений больше не управляет: новая работа отныне обычное правило, а не
последствие нажатия. END остаётся явной пометкой «с чистого листа» — она
выбранным режимом ставит ACTION и отвечает человеку, но маршрут теперь тот же
у любого поручения без reply.

## Почему

- **У моста нет адреса у сообщения без reply.** Он не знает, к какому из своих
  писем относится такой текст; наугад продолжать последнюю сессию — засорять её
  чужим разговором. Эту же беду когда-то лечили кнопкой END (062): «любое
  сообщение уходило в последнюю сессию, и разговор о другом деле засорял чужой
  контекст». Раз END для этого был заведён, правило обобщено на всякое сообщение
  без reply: вернуться в старую работу по-прежнему можно только реплаем на её
  письмо.
- **Классификатор идёт раньше маршрута.** Слова «стоп», «что там», «спасибо»
  без reply по-прежнему действуют на работу, а не заводят новую: поручение,
  связь которого с ходом «продолжение», — всегда reply.
- **Вдогонку — не новая работа.** Единственная цена строгого правила — человек,
  дописывающий поручение по частям, получил бы на каждую реплику новую сессию.
  Поэтому, пока работа идёт, адресат у сообщения без reply — она.

## Стандарт

Подходящего публичного стандарта нет (исключение с ценой): это маршрутизация
сообщений личного бота, внешне проверяемая только живой перепиской. Цена —
поведение на живом ответе владельца проверяется вручную, автоматом гоняется
обход решений инбокса на фейковых обновлениях без сети (см. «Что проверено»).

## Чем платим

- Сессионная память направлений разделилась: «продолжить» — только reply,
  включая случай, когда reply-сообщение не нашлось (упиралось в чужой чат,
  старое письмо за пределами памяти 500 сообщений) — такое тоже заводит новую
  работу, а не «последнюю сессию».
- Флаг fresh теперь про подсказки кнопок, а не про маршрут: клавиатура его
  читает, когда рисует тексты под END и ACTION.

## Что проверено

Обход решений инбокса на фейковых обновлениях без сети, классификатор
заглушён явными intent'ами (node TOOLS/telegram-inbox-check.js, 14 писем,
в ногу с проверкой из 062): поручение без reply — новая работа, привязанная
к личке; после окончания работы так же; «стоп» без reply не заводит
работу и останавливает идущую; «ок» без reply — «👌»; «что там» без reply —
статус, без ходов и работ; reply по таблице «чат + сообщение → сессия» уходит
в свою сессию и как поручение, и как «стоп»; письмо вдогонку идущему ходу
отвечается в неё же; reply на письмо забытой (удалённой) сессии заводит новую,
а не уходит в последнюю; сообщение чужого чата отбрасывается молча.
`node --check` правленых файлов и `npm run check` (EXIT=0) — до коммита.
Проверка ручная и в `npm run check` не входит: стадию в общий gate не добавляли,
пока она не обкатана по 034.

Связь: 024 (последний ответ сессии уходит человеку), 062 (END), 054 (разбор
служебных слов), 052 (мост переживает перезапуск).

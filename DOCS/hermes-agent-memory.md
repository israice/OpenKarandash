# Research: память и самообучение Hermes Agent

> Дата: 2026-10-22. Источники: официальные docs (hermes-agent.nousresearch.com/docs) и
> репозиторий [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent) (MIT,
> «The agent that grows with you»).
> Релевантно для OpenKarandash: our stack клонирует hermes-agent при старте сервера
> (`SYSTEM/core/hermes-stack.js`), а `hermes-home/` — его рантайм-данные.

## TL;DR

Hermes — «самоулучшающийся» агент с замкнутой петлёй обучения: сам создаёт скиллы из опыта,
сам улучшает их в использовании, сам сохраняет знания после каждого хода (фоновый review),
ищет по своим прошлым сессиям (FTS5) и углубляет модель пользователя между сессиями.

## 1. Осведомлённость о сессиях (эпизодическая память)

- Каждый диалог (CLI, Telegram, Discord, Slack, WhatsApp, Signal, Matrix, cron, API, batch…)
  автоматически сохраняется как сессия в **SQLite `~/.hermes/state.db`**:
  - ID, платформа-источник, user ID, уникальный человекочитаемый title (авто-генерация
    3–7 слов быстрой aux-моделью);
  - модель, **снапшот системного промпта**, полная история (role, content, tool calls/results),
    счётчики токенов, timestamps, `parent_session_id` (родословная при компрессии:
    «my project» → «my project #2» → «#3»).
- Полотекстовый поиск **FTS5** прямо в той же БД (есть CJK-расширение `native/fts5_cjk`):
  - запрос ~20ms, скролл внутри сессии ~1ms;
  - БЕЗ LLM-суммаризации и обрезки — возвращаются реальные сообщения;
  - три формы вызова `session_search`: discovery / scroll / browse.
- Резюм: `hermes -c` / `--resume` (recap-панель, восстановление рабочей директории,
  per-terminal breadcrumb, lineage по имени); чат мессенджера — одна непрерывная сессия,
  переживает рестарты/ребуты; `/handoff <platform>` переносит живой CLI-диалог на платформу.
- Медиа — turn-scoped: сырые байты в будущие промпты не копируются, только описание/путь.

## 2. Слои памяти (от дешёвого к дорогому)

| Слой | Что это | Ёмкость | Когда доступен |
|---|---|---|---|
| Контекст-файлы (`AGENTS.md`, `SOUL.md`) | проект / персона | — | каждый ход |
| `MEMORY.md` | заметки агента: окружение, конвенции, уроки, «дневник выполненных работ» | 2200 симв (~800 ток) | снапшот в system prompt на старте сессии |
| `USER.md` | профиль пользователя: предпочтения, стиль общения | 1375 симв (~500 ток) | там же |
| Скиллы (`~/.hermes/skills/`) | процедурная память: методики, ловушки, команды | не ограничена | по требованию (progressive disclosure: индекс ~3k ток → SKILL.md → references/) |
| Session search (FTS5) | эпизодическая память: вся история диалогов | не ограничена | по требованию, бесплатно |
| Внешние провайдеры | Honcho, Mem0, Hindsight, RetainDB, ByteRover, Supermemory… | на стороне бэкенда | *рядом* со встроенной, никогда не вместо |

Механики встроенных файлов:

- **Frozen snapshot**: память инжектится в system prompt один раз при старте сессии; запись
  идёт на диск сразу, видна со следующей сессии. Сознательная защита prompt-кэша.
- **Агент — сам себе куратор**: tool `memory` с действиями `add` / `patch` / `remove`
  (sub matching), один target на вызов (`memory` или `user`); действия `read` нет.
- Переполнение ≠ молчаливое вытеснение: tool возвращает ошибку + текущие записи, и агент
  **в тот же ход** консолидирует/укорачивает старые (лимит проверяется на итог батча).
  Правило: >80% заполнения — сливать родственные записи.
- Дубликаты отклоняются; записи сканируются на prompt-injection, эксфильтрацию секретов
  и невидимые Unicode; опциональный гейт `memory.write_approval` (`/memory pending` →
  approve/reject), включая фоновые автозаписи.
- Разделение ролей: факт нужный всегда → память; процедура нужная иногда → скилл
  (не конкурирует за бюджет 2200 символов).

Honcho (dialectic user modeling, Plastic Labs; `hermes plugins install honcho`):
два слоя инъекции в каждый ход — base context (session summary + user representation +
peer card, по `contextCadence`) и dialectic supplement (LLM-рассуждение «что важно сейчас»,
по `dialecticCadence`, multi-pass глубина 1–3: audit → reconcile). Cold/warm промпт:
без базы — «кто этот человек», в прогретой сессии — «что релевантно сейчас».
Conclusions копятся на сервере → semantic search по паттернам пользователя.

## 3. Петля самосовершенствования

- **Background self-improvement review** (сердце петли): после каждого хода фоновый форк
  того же AIAgent проигрывает разговор и решает, чему научиться:
  повторяющиеся поправки и уроки workflow → записи MEMORY/USER или патчи скиллов;
  интервалы `memory.nudge_interval` / `skills.creation_nudge_interval` (~каждые 10 ходов
  для скиллов). Можно вынести на дешёвую модель (`auxiliary.background_review` →
  replay digest, в 3–5× дешевле), `max_input_tokens` (=75% окна) ограничивает стоимость,
  на локальном GPU review откладывается до простоя (defer).
- **Скиллы**: системный промпт требует сохранять нетривиальный workflow через
  `skill_manage` (create/patch/write_file/…). Линтер-советник, правило «lessons, not logs»
  (обобщённые правила + одна фраза «почему»; без инцидентов и номеров PR). `/learn` —
  любой источник → скилл; большие источники → knowledge-base skill (SKILL.md с
  ментальными моделями + по файлу на главу в `references/`).
- **Curator** (background-библиотекарь): телеметрия `.usage.json` (view/use/patch);
  детерминированные переходы без LLM: 14 дней неиспользуем → stale, 30 → архив
  `.archive/` (восстановим); pinned и cron-упомянутые — неприкосновенны; опциональный
  LLM-консолидейшн (off по умолчанию, tar.gz-снапшот перед проходом, rollback);
  append-only ledger всех мутаций (before/after SHA-256) с откатом одиночной мутации.
- **Сессионные границы**: петля «забыл → вспомнил из памяти → нашёл в прошлых сессиях»
  запускается только на границе сессии; в мессенджер-чате без `/new` она стреляет редко
  и дорожает — рекомендация авторов: `/new` на границе задачи/темы/дня.
- **`/journey`**: шкала всего выученного (скиллы + память по времени), «Star Map» в
  Desktop; там же edit/prune «знаний».
- **Обучение моделей**: batch trajectory generation + trajectory compression — сессии
  экспортируются как трейсы (Claude Code JSONL → HF Agent Trace Viewer / приватный HF
  dataset с `--redact`) для тренировки следующего поколения tool-calling моделей.

## 4. Для OpenKarandash

- `hermes-home/` = его `~/.hermes`: `state.db` (сессии + FTS5), `memories/`
  (MEMORY.md/USER.md), `skills/`.
- **Главное предостережение**: не направлять два агент-процесса в один hermes-home —
  память скомпаундится записями двух авторов. Второму агенту — отдельный профиль
  (`hermes -p work` → `profiles/work/memories/`); общая память — внешний memory provider.
- Гейты (`memory.write_approval`, `skills.write_approval`) полезны в общем/автоматическом
  стеке, чтобы фоновое самообучение не меняло профиль без одобрения.

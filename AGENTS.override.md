Спорное место искать в тематических файлах — повторов тут намеренно нет, кроме первого абзаца `DOCS/agents/конвенции.md`.

## Домашняя работа — до первого хода

**`node TOOLS/homework/run.mjs "текст задачи"`** — один шаг вместо тридцати: скрипт сам найдёт файлы, отдаст их с диапазонами строк, правилами типа задачи и командой проверки. Текст задачи сюда идёт вместе со строкой `UI element:` от клика по элементу — она даёт точные якоря. В замере на трёх задачах разведка стоила 122 шага, с ним — 37 (`DOCS/decisions/084`). **Отчёт пустой — это не беда, а ответ:** значит, место описано словами и спросить у человека, какой элемент трогать, дешевле тридцати шагов впустую.

Дальше — только правка и одна проверка. Правила ниже — на случай, когда отчёт не помог или его нет.

## Пять правил, которые экономят больше всего

1. **Поиск — сначала `node PROJECTS/Graph/search.js "2–4 ключевых слова вместе"`.** Grep и find по репозиторию — не первый шаг (`DOCS/agents/карта-проекта.md`).
2. **Не читай файл, в котором не меняешь ни строчки.** Точный поиск или grep по классу уже дал ответ — источник не нужен. Имя класса в разметке плюс сам CSS-файл достаточны для правки стилей.
3. **Правка стилей — один CSS-файл элемента** (`SYSTEM/styles/*.css` либо `PROJECTS/<Фича>/*.css`), проверка — числа, а не картинка: `node TOOLS/live-verify/run.mjs styles select=<селектор>` отдаёт фон и цвет выбранного и невыбранного пункта.
4. **Снимок в контекст не открывай без нужды:** картинка дороже любого текста, а раскрытый список нативного `select` в снимок вообще не попадает — проверить им цвет пункта нельзя.
5. **Из проверки возвращай 2–3 репрезентативных значения, а не весь список.** Дамп всех пунктов селекта (их бывает 50) стоит дороже самой правки.

## Чем читать и чем искать

- Текст проекта — инструментом чтения и grep, а не консолью: консоль отдаёт русский текст кракозябрами, и на чтение файла уходит лишняя итерация.
- Состояние дерева — по путям: `git status --porcelain -- <пути>`; целиком оно выдаёт сотни чужих правок других сессий.
- Bash-поиском никогда не трогать `DATA/`, `.git/`, `node_modules/` и `*.db*` (там индексы и бинарники).
- Комментарии в коде — на русском. Ответ в чате — всегда на языке текущего сообщения пользователя.

## Куда лезть по типу задачи

| Что правишь | Где это лежит | Чем проверить | Что прочитать сверх этого |
|---|---|---|---|
| Стили элемента | `SYSTEM/styles/*.css`, `PROJECTS/<Фича>/*.css` | `npm run check`, `run.mjs styles select=<селектор>` | — |
| Клиентский скрипт, разметка | файл раздела в `PROJECTS/<Раздел>/` или `SYSTEM/` | `npm run check`, `npm run ui`, сценарий под правку | `DOCS/agents/клиент.md` |
| Серверная половина фичи | `PROJECTS/<Фича>/*-server.js` | `npm run check`, сценарий с POST-запросом | `DOCS/agents/сервер.md` |
| Страница кнопки «+» | новая папка в `PROJECTS/` | `npm run ui`, `run.mjs open page=<папка>` | `DOCS/agents/клиент.md` |
| Лента, роль или поле сессии | файлы раздела Sessions | сценарий `three-views` — сверка трёх отображений | `DOCS/agents/конвенции.md` (три отображения — один источник, `DOCS/decisions/039`) |
| Записка, решение, версия | `DOCS/decisions/`, `VERSION.md` | машинно нечего: поиск по vault подхватит сам | — |

Новая роль, поле или пометка сессии заводится сразу в трёх отображениях (Sessions, Feed и Flow < TEMP < 321) и проверяется во всех трёх — они рисуют одни и те же строки, расхождение между ними дефект (`DOCS/decisions/039`).

## Перед «готово» — обязательное

- `npm run check` — один раз, после всех правок, до коммита: неизвестные имена, циклические связи, длинные файлы.
- Живая проверка — на сервере, который поднял владелец: `npm run ui` и сценарии `TOOLS/live-verify/` (обёртка `run.mjs`). **Сервер из сессии не поднимать ни в фоне, ни на переднем плане** (`DOCS/decisions/002`) — об этом подробно в `DOCS/agents/проверка.md`.
- Коммит: только файлы этой задачи, поимённо, никогда `git add -A`; строка версии `vX.Y.Z - …` дописывается в конец `VERSION.md` и входит в тот же коммит, первой строкой сообщения идёт она же. Пуш — только по явной просьбе.
- Финальный ответ по законченной задаче — три абзаца человеческим языком, без списков, имён файлов и слов вроде «коммит» и «функция» (формат — в `DOCS/agents/конвенции.md`).

Мелочи, которые в сессии уже набили осколки: правило целиком в `DOCS/agents/проверка.md`, почему одна поломка не должна гасить интерфейс — в `DOCS/agents/перезагрузка.md`, как не тратить шаги — в `DOCS/agents/измерения.md`.

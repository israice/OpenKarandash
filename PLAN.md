# План уборки кода

Цель — подготовить проект к разделению на модули, не нарушив принцип «ноль зависимостей».

Состояние на старте (v0.0.4):

| Файл | Объём | Из чего состоит |
| --- | --- | --- |
| `index.html` | 3666 строк | CSS 8–1734, разметка 1736–2042, инлайновый JS 2043–3664 (108 функций) |
| `server.js` | 939 строк | HTTP-статика, live-reload, самоперезапуск, коннектор Claude CLI, SQLite-сессии |

Автоматических проверок нет ни одной. Это главный риск: любой распил идёт вслепую.

Порядок важнее списка — шаги идут строго сверху вниз.

## 1. Страховка перед уборкой

Без неё остальные шаги — азартная игра. Делается до любого перемещения кода.

- [x] `smoke.js` в корне: поднимает сервер на свободном порту и проверяет HTTP-уровень —
      `/` отдаёт страницу, несуществующий путь даёт 404, попытка выйти за корень даёт 403,
      запрос с нелокального адреса даёт 403, GET к `/api` даёт 405, `POST /api/sessions`
      возвращает список. Ноль зависимостей,
      запуск `node smoke.js`, выход ненулевым кодом при провале.
      Сделано в v0.0.5: 7 проверок, все зелёные. Описание — в README.
- [ ] Чек-лист UI-смоука (ниже) — прогоняется через Playwright MCP вручную после каждого
      шага раздела 5. В репозиторий как тест не ложится: playwright — это зависимость,
      а проект принципиально без них.

UI-смоук, минимальный набор:

1. Страница грузится, консоль браузера без ошибок.
2. Переключение вкладок Chat / Settings.
3. Settings: провайдер Claude виден, кнопка «Подключить» открывает результат поиска CLI.
4. Chat: сообщение уходит и возвращается ответом в ленту.
5. Панель Sessions: сессия появилась, клик по ней открывает переписку.
6. Перезагрузка страницы: подключение и сессия восстановились.

## 2. Разведка безопасности

- [ ] `/security-review` по `server.js`. Разово, до переездов кода: сервер запускает процессы
      (`spawn`, `wsl.exe bash -lc`) и раздаёт файлы с диска — эти места должны быть проверены
      в текущем виде, пока их легко читать.

## 3. Разведка дефектов

- [ ] `/code-review high` по `server.js`
- [ ] `/code-review high` по `index.html`

Смысл — до рефакторинга, чтобы не тащить существующие баги в новую структуру, где они
будут выглядеть свежими. Уровень `high` даёт широкий охват; часть находок будет
неуверенной, это ожидаемо для разведки.

## 4. Архитектурное решение

- [ ] Агент `Plan` на один вопрос: как разложить инлайновый `<script>` из `index.html`.

Ключевой факт для решения: браузерные ESM (`<script type="module">` + `import`) работают
без сборщика, то есть распил возможен без единой зависимости. Сервер уже отдаёт файлы
с нужным MIME.

Побочный эффект, который нельзя забыть: `.claude/hooks/syntax-check.js` намеренно
пропускает скрипты с атрибутами, включая `type="module"`. При переезде хук надо доучить,
иначе проверка синтаксиса молча перестанет покрывать основную часть кода.

## 5. Распил, по одному модулю за шаг

- [ ] Выделить первый модуль, прогнать `smoke.js` + UI-смоук
- [ ] `/simplify <путь>` по выделенному модулю
- [ ] Повторять, пока `<script>` не опустеет

Порядок модулей определяется на шаге 4. После каждого шага — рабочее приложение
и зелёный смоук; больше одного модуля за раз не двигать.

## 6. CSS — последним

- [ ] Вынести 1726 строк `<style>` в `styles.css`

Отложено намеренно: это самая крупная и самая безобидная часть файла, выносится одной
операцией в любой момент и ничего не разблокирует.

## Чего в плане нет и почему

**Многоагентный `workflow` / `/code-review ultra` по всему проекту.** На 4600 строках даст
длинный список наблюдений, исполнять который всё равно руками, при заметно большей цене.
Ultra оправдан на конкретном большом диффе — например, когда распил из раздела 5 будет
готов к ревью целиком.

**Смена архитектуры сервера.** `server.js` на 939 строк читается целиком и проблемой не
является. Трогать его до того, как разобран `index.html`, — работа не по приоритету.

**Добавление сборщика, фреймворка, тест-раннера.** Нарушает принцип проекта, зафиксированный
в `CLAUDE.md`.

## 1. Страховка перед уборкой

Без неё остальные шаги — азартная игра. Делается до любого перемещения кода.

- [x] `smoke.js` в корне: поднимает сервер на свободном порту и проверяет HTTP-уровень —

      запрос с нелокального адреса даёт 403, GET к `/api` даёт 405, `POST /api/sessions`
      возвращает список. Ноль зависимостей,
      запуск `node smoke.js`, выход ненулевым кодом при провале.
      Сделано в v0.0.5: 7 проверок, все зелёные. Описание — в README.

UI-смоук, минимальный набор:

## 2. Разведка безопасности

- [x] `/security-review` по `server.js`. Разово, до переездов кода: сервер запускает процессы
      (`spawn`, `wsl.exe bash -lc`) и раздаёт файлы с диска — эти места должны быть проверены
      в текущем виде, пока их легко читать.

Скилл не запустился: он строит диапазон от `origin/HEAD`, а remote в репозитории нет.
Ревью проведено чтением `server.js` целиком. Найдено четыре дыры, все подтверждены.

### 2.1. Инъекция команд через `sessionId` (критично)

`server.js:756` — `sessionId` из тела запроса уходит в `args.push('--resume', sessionId)`
без всякой проверки, а `runClaude()` при `target.viaShell` (WSL на Windows) склеивает
аргументы в одну строку для `bash -lc`. Значение `abc; touch ВЗЛОМАНО` даёт:

```
bash -lc "claude -p ... --resume abc; touch ВЗЛОМАНО --permission-mode bypassPermissions"
```

Комментарий над `runClaude()` обещает, что в командную строку ничего не попадает —
это верно для промпта (он идёт через stdin), но не для `sessionId`. `model` и `effort`
сверяются со списками, `sessionId` — нет.

Чинить: проверять формат id (UUID) перед подстановкой.

### 2.2. Нет защиты от запросов со сторонней страницы (высокий)

`/api/*` не смотрит ни на `Origin`, ни на `Sec-Fetch-Site`. Любая открытая в браузере
страница может послать `POST /api/claude/ask` с `mode: "Action"` — это простой запрос,
preflight для него не требуется, значит CORS его не остановит. Ответ злоумышленник
не прочитает, но запуск уже произошёл, а Action идёт с `bypassPermissions`.

Чинить: отклонять запрос, если `Origin` присутствует и не совпадает с собственным.

### 2.3. Сервер слушает на всех интерфейсах (высокий)

`server.js:930` — `server.listen(port, ...)` без адреса, то есть `0.0.0.0`. Защищает
только проверка `isLocalRequest()` в коде. Порт при этом открыт для всей локальной сети,
и любая ошибка в проверке сразу превращается в удалённое исполнение кода.

Чинить: `server.listen(port, '127.0.0.1', ...)` — тогда внешние соединения отсекает ОС,
а проверка в коде остаётся вторым рубежом.

### 2.4. Скрытые файлы раздаются по HTTP (средний)

Фильтр `startsWith('.')` есть только в `snapshot()` — в раздаче статики его нет.
Проверено на живом сервере: `GET /DATA/.sessions.db` отдаёт 487 424 байта (вся переписка
со всеми сессиями), `GET /.git/config` — 314 байт. Сам по себе это локальный доступ,
но вместе с 2.3 файлы видны из сети.

Чинить: отдавать 404 на пути, где любой сегмент начинается с точки.

## 4. Архитектурное решение

- [ ] Агент `Plan` на один вопрос: как разложить инлайновый `<script>` из `index.html`.

Ключевой факт для решения: браузерные ESM (`<script type="module">` + `import`) работают
без сборщика, то есть распил возможен без единой зависимости. Сервер уже отдаёт файлы
с нужным MIME.

Побочный эффект, который нельзя забыть: `.claude/hooks/syntax-check.js` намеренно
пропускает скрипты с атрибутами, включая `type="module"`. При переезде хук надо доучить,
иначе проверка синтаксиса молча перестанет покрывать основную часть кода.

## Чего в плане нет и почему

**Многоагентный `workflow` / `/code-review ultra` по всему проекту.** На 4600 строках даст
длинный список наблюдений, исполнять который всё равно руками, при заметно большей цене.
Ultra оправдан на конкретном большом диффе — например, когда распил из раздела 5 будет
готов к ревью целиком.

**Смена архитектуры сервера.** `server.js` на 939 строк читается целиком и проблемой не
является. Трогать его до того, как разобран `index.html`, — работа не по приоритету.

**Добавление сборщика, фреймворка, тест-раннера.** Нарушает принцип проекта, зафиксированный
в `CLAUDE.md`.

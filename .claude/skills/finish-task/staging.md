# Индекс среди чужих правок

Читать, когда `git status` показывает не только твои файлы или в твоём файле есть чужие куски. Сессии идут параллельно в одной рабочей копии (`AGENTS.override.md`, «Устройство сервера»), файлы под ними никто не блокирует — поэтому в основной папке почти всегда лежит чужая незакоммиченная работа, в том числе в тех же файлах, что правил ты.

Своё — то, что ты сам вносил в этой сессии. Всё остальное чужое. Сомневаешься — кусок чужой: чужой кусок, оставшийся незакоммиченным, безвреден, а ушедший под твоей версией — нет.

`$S` ниже — папка для временных файлов сессии (scratchpad), не папка проекта.

## Файл твой целиком

```bash
git add -- "PROJECTS/Flow/flow.js" "DOCS/decisions/051-тема.md"
```

Только поимённо. `git add -A`, `git add .`, `git commit -a` запрещены правилом автокоммита.

## В файле есть чужие куски

`git add -p` интерактивный и в сессии не работает. Вместо него — `pick-hunks.js` из папки навыка (только читает, патч кладёшь ты):

```bash
node .claude/skills/finish-task/pick-hunks.js server.js                          # куски с номерами, счёт с нуля
node .claude/skills/finish-task/pick-hunks.js server.js 1,3-5 --out "$S/mine.patch"   # патч из своих
git apply --cached --unidiff-zero "$S/mine.patch"
git diff --cached -- server.js                                                   # в индексе только своё?
```

Куски берутся без контекста, позиции в заголовках скрипт пересчитывает сам — вручную патч не править. Если после первого захода вспомнил ещё кусок — запусти список заново: номера считаются от того, что ещё не в индексе.

## Своё и чужое слиплись в один кусок

Так бывает с соседними строками — типичный случай `VERSION.md`: параллельная сессия дописала свою строку версии и ещё не закоммитила, твоя легла сразу под ней. Кусок не делится, поэтому содержимое для индекса собирается отдельно: то, что в индексе сейчас, плюс твоё.

```bash
git show :VERSION.md > "$S/VERSION.index"
printf '%s\n' 'v0.0.41 - что сделано' >> "$S/VERSION.index"
git update-index --cacheinfo "100644,$(git hash-object -w "$S/VERSION.index"),VERSION.md"
git diff --cached -- VERSION.md        # ровно одна добавленная строка — твоя
```

Индекс так собирают отдельным вызовом до `git commit`, а не одной цепочкой с ним: всё, что проверяет коммит (сверка `audit-commit.js`, хуки), смотрит индекс на момент своего запуска и правку через `git update-index` из той же команды не увидит.

Чужая строка остаётся в рабочей копии нетронутой, её закоммитит хозяин. Номер бери после чужого (его и показывает `next-numbers.js`): две сессии с одной версией — то, ради чего номер считает скрипт. Для другого файла тот же приём: собрать во временном файле «версия из индекса + только мои правки» и положить её через `git hash-object -w` и `git update-index --cacheinfo`.

## Положил лишнее

```bash
git restore --staged -- путь/к/файлу     # трогает только индекс, рабочая копия цела
```

Никогда: `git stash`, `git checkout -- <файл>`, `git restore <файл>` без `--staged`, `git reset --hard`, `git clean` — они стирают чужую незакоммиченную работу, которую никто не восстановит.

## Что не идёт в коммит никогда

- `hermes` — в индексе это ссылка на коммит чужого клона (gitlink), сам клон обновляет стек при старте сервера, поэтому ссылка «грязная» всегда. `git status` её не показывает только из-за `diff.ignoreSubmodules=all` (`DOCS/decisions/041`); инструмент, который эту настройку не читает (например, стартовый снимок состояния в сессии), покажет `M hermes`. Это не твоя правка.
- `exec-bridge/__pycache__/*.pyc`, `hermes-plugins/model-providers/claude-bridge/__pycache__/*.pyc` — кеш Python, когда-то попавший в git; меняется сам при каждом запуске мостов.
- `.env` и всё из `DATA/` (в том числе сценарии живой проверки в `DATA/live/`).

## Git занят

`fatal: Unable to create '…/.git/index.lock': File exists` — в эту секунду git выполняет параллельная сессия. Подожди и повтори команду; файл блокировки не удаляй.

## Сверка перед коммитом и после

```bash
node .claude/skills/finish-task/audit-commit.js          # индекс: строка версии, её место, дубль номера записки, hermes/кеш
node .claude/skills/finish-task/audit-commit.js --head   # готовый коммит: заголовок равен строке версии
```

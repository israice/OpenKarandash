# Завершение задачи

Само правило — в `AGENTS.override.md`: «Конвенции» (автокоммит по завершении задачи, отчёт в три абзаца) и «Проверка изменений» (`npm run check`, `npm run ui`, память работника). Здесь — порядок шагов и числа, которые нельзя считать на глаз. Разошлись навык и правило — верно правило, навык поправь.

Id задачи beads, если передан при вызове: $ARGUMENTS

## Живые факты

Сняты скриптом `next-numbers.js` в момент загрузки навыка:

!`node "${CLAUDE_SKILL_DIR}/next-numbers.js"`

Числа устаревают: сессии идут параллельно в одной рабочей копии. Перед созданием записки и перед строкой версии сними их заново — `node .claude/skills/finish-task/next-numbers.js`. Так же поступи, если блок выше пуст, в нём сказано, что запуск команд отключён, или вместо вывода видна сама команда (файл читает не Claude Code).

Почему считает скрипт. Номера записок 010, 012, 026 и 039 заводились дважды: автор брал «последний + 1» из того, что видел сам, а соседняя записка писалась в ту же минуту в той же пачке или в параллельной сессии. Дубли потом разводили руками: 026 → 029 (один номер в двух ветках), 039 → 041 (две записки одной пачкой) — с правкой всех ссылок. Скрипт смотрит шире, чем `ls`: записки на диске во всех рабочих копиях (значит, и ещё не закоммиченные чужой сессией) плюс всё, что когда-либо добавлялось в историю любой ветки, — номер удалённой записки тоже занят. Версию он берёт как наибольшую из строк `VERSION.md` на диске и заголовков недавних коммитов. Гонку это сужает, но не убирает: номер занят только тогда, когда файл записки или строка версии уже лежат на диске, — поэтому пиши их сразу после запуска скрипта, а перед коммитом сверяйся шагом 7.

## Порядок

Шаги идут подряд. Упавший шаг чинят, а не обходят; что проверить не удалось — называют прямо в сообщении коммита и в ответе. Блоки команд ниже копируются как есть, без отступа: строка `EOF` с пробелами перед ней heredoc не закрывает.

### 1. Машинная проверка

`npm run check` отдельным шагом, не фоном. Упала — не коммить и скажи об этом. Неизвестные имена и циклические связи валят команду, список файлов длиннее 400 строк только печатается. Новое имя, публикуемое через `window`, дописывается в `APP_GLOBALS` в `eslint.config.mjs`. Копию ветки проверяют из главной копии: `npm run check -- --root <абсолютный путь копии>` (это же первым шагом делает `npm run gate -- <ветка>`).

### 2. Живой интерфейс

Если правил клиент (`SYSTEM/`, клиентские файлы `PROJECTS/<Фича>/`, шаблоны `.eta`, стили): `npm run ui`. Код 1 — замечания, чинить; код 3 — отсюда прогнать нельзя, записать как непроверенное. Прогон идёт на сервере, который поднял владелец.

### 3. Живая проверка сценария

Прогон видит только, что вкладки открылись непустыми и без ошибок. Работает ли сама правка, проверяешь ты, а не владелец: сценарий под задачу через `SYSTEM/live-check.mjs` (как запускать — в шапке файла; тело сценария клади в `DATA/live/`, она не коммитится). Если в `.claude/skills/` есть навык `live-verify` — веди сценарий по нему. Правка ленты или событий хода сверяется во всех трёх отображениях: Sessions, Feed, Flow. Всё, что для проверки надо включить (например, подключить CLI через `/api/agent/connect`), включаешь сам; к владельцу идёшь только с тем, что тебе действительно недоступно, и называешь, что именно и почему.

Сервер владельца не поднят — свой не поднимать: ни сервер, ни мосты, ни Hermes, даже ради проверки. Тогда в коммите и в ответе честно стоит «живьём не проверено», а задача beads остаётся открытой.

### 4. Записка решения

Только если ответ на «почему так» из кода не виден. Номер — из `next-numbers.js`, запущенного прямо сейчас; файл `DOCS/decisions/NNN-тема-через-дефисы.md` создай сразу. Одна записка — одно решение; разделы «Решение», «Почему», «Чем платим», по делу — «Что проверено» (`DOCS/decisions/README.md`). Отменённое решение не удаляют, а помечают в самой записке, и новая записка называет, что она отменяет. Фразы в `AGENTS.override.md`, которые решение сделало неверными, правятся в этой же задаче.

### 5. Память работника

Только проверенный приём, который пригодится в похожей задаче; «наверное, помогает» не пишут вовсе (`DOCS/decisions/035`). Роль — имя папки в `PROJECTS/Flow/profiles/`. Путь по правилу — `POST /api/flow/profile/memory/add` с JSON: `profile`, `title`, `how` обязательны, `when`, `proof`, `session` желательны; дату ставит сервер; ответ `{ ok: true, file }` либо `{ ok: false, error }` с кодом 200. Из WSL сервер отвечает 403 на любой прямой запрос, поэтому маршрут зовут со страницы пульта — телом сценария `live-check.mjs`:

```js
return await (await fetch('/api/flow/profile/memory/add', { method: 'POST', headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ profile: 'Backend developer', title: '…', when: '…', how: '…', proof: '…', session: '…' }) })).json();
```

Сервер не поднят — вызови ту же функцию, что стоит за маршрутом; запись выйдет той же, а модуль сервер не запускает (команда — из корня рабочей копии):

```bash
node - <<'EOF'
const { appendSkill } = require('./PROJECTS/Flow/profiles-server.js');
console.log(appendSkill('Backend developer', {
    title: 'Название приёма',
    when: 'Когда применим',
    how: 'Что делать — конкретными командами',
    proof: 'Чем подтверждён',
    session: 'id сессии или задачи',
}));
EOF
```

Файл `PROJECTS/Flow/profiles/<Роль>/memories/skills.md` — часть коммита этой задачи.

### 6. Строка версии

Только в главной копии (ветка `main`); в копии ветки исполнителя её не пишут, версия принадлежит коммиту, который приземлится в `main`. Запусти `next-numbers.js` ещё раз и допиши в самый конец `VERSION.md` одну строку `vX.Y.Z - что сделано`: обычный дефис с пробелами, человеческим языком о том, что изменилось для пользователя пульта, без имён файлов. Файл кончается переводом строки. Пульт берёт номер версии из последней такой строки, а список версий — из всех.

### 7. Индекс — только своё, поимённо

`git add -- <файл> <файл>`. Никогда `git add -A`, `git add .`, `git commit -a`. В файле есть чужие куски или рядом с твоей строкой версии лежит чужая — рецепты в [staging.md](staging.md). Никогда не идут в коммит `hermes`, `__pycache__/*.pyc`, `.env`. Затем сверка отдельной командой, до коммита: `node .claude/skills/finish-task/audit-commit.js` — она же печатает строку, которой должен равняться заголовок коммита.

### 8. Коммит

Одна задача — один коммит. Первая строка сообщения совпадает со строкой версии посимвольно. Дальше по-русски, человеческим языком: id задачи beads или «Задачи в beads нет: почему»; затем «Проверено: …» и «Не проверено: …» — честно, без округления в свою пользу. В конце — строка авторства `Co-Authored-By:`, которую даёт текущая сессия.

```bash
git commit -q -F - <<'EOF'
vX.Y.Z - что сделано

Задача OpenKarandash-xxx. Что и зачем изменено — двумя-тремя фразами.

Проверено: …
Не проверено: …

Co-Authored-By: …
EOF
node .claude/skills/finish-task/audit-commit.js --head
```

Пуш — только по явной просьбе владельца. Отказ хука на `git add` или `git commit` означает пропущенный шаг ритуала: устрани причину, а не обходи хук.

### 9. Задача beads

Закрывается только после пройденной живой проверки: `bd close <id> --reason "что проверено"`. Проверки не было — задача остаётся открытой, а что осталось проверить, пишется в неё: `bd comment <id> "…"`.

### 10. Финальный ответ

Уходит владельцу в телеграм как есть, поэтому это отчёт руководителю, а не техническая сводка: три абзаца на языке последнего сообщения пользователя — что просили; что сделано; что это улучшит и как теперь будет работать. Без списков, без имён файлов, функций и номеров строк, без слов «коммит», «функция», «рефакторинг». Упавшая проверка и всё непроверенное называются в этих же абзацах простыми словами.

## Ловушки

- Чужая незакоммиченная работа в той же папке — норма. Её не коммитят, не откатывают и не прячут: `git stash`, `git checkout -- <файл>`, `git restore <файл>`, `git reset --hard`, `git clean` здесь запрещены. Лишнее убирают только из индекса: `git restore --staged -- <файл>`.
- `hermes` «грязный» всегда: в индексе лежит ссылка на коммит чужого клона, а клон обновляет стек при старте сервера. `git status` молчит о нём только из-за `diff.ignoreSubmodules=all` (`DOCS/decisions/041`); увидел `M hermes` в другом инструменте — это не твоя правка.
- В git когда-то попал кеш Python (`exec-bridge/__pycache__/`, `hermes-plugins/model-providers/claude-bridge/__pycache__/`) — он меняется сам при запуске мостов и к задаче не относится.
- `index.lock: File exists` — git занят параллельной сессией: подожди и повтори, файл не удаляй.
- Строка версии без коммита и коммит без строки версии одинаково неверны: список версий в пульте строится из `VERSION.md`, а не из `git log`. Из-за пропущенной строки уже приходилось переписывать историю.

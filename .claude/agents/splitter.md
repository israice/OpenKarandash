Ты один из нескольких splitter'ов, которые **одновременно** правят разные файлы. Поэтому границы жёсткие:

- Правишь только файл из задания и создаёшь только файлы из его таблицы, в той же папке (или в папке, названной в задании).
- `SYSTEM/index.html` не трогаешь: нужные `<script>`/`<link>` перечисляешь в отчёте точными строками.
- Чужие папки и чужие файлы не трогаешь. Если правка нужна снаружи — в отчёт, не в код.
- Перед стартом прочитай целиком `DOCS/decisions/022-один-файл-одна-тема.md` и разделы «Устройство сервера» и «Клиентский код» в `AGENTS.md` — правила там, здесь только порядок работы.

## Порядок

1. Прочитай исходный файл целиком один раз. Составь для себя карту: какие функции ходят в какое общее состояние (переменные замыкания или верхнего уровня) и кто кого зовёт.
2. Найди внешних потребителей каждого публичного имени: `grep -rn "window.Имя\|Имя\." SYSTEM PROJECTS` и `node PROJECTS/Graph/search.js "Имя"`. Всё, что используется снаружи, остаётся под прежним `window.*` / `module.exports` без переименований.
3. Перенос — механический. Код переносится как есть: без попутных улучшений, без переименований, без изменения поведения, с теми же комментариями (на русском). Единственные новые строки — `import`/`export`/`require`/`module.exports` и `state.` перед общей переменной.
4. Общее изменяемое состояние → один модуль: на клиенте `<вкладка>-state.js` с `export const state = {…}`; на сервере — объект, который передаётся аргументом. `export let` запрещён.
5. Обработчики, которые висели на верхнем уровне IIFE (`document.addEventListener`, `window.addEventListener`), и любые `document.querySelector` на верхнем уровне — переезжают в `init()` входа.
6. Исходный файл после разъезда — только вход: подключение частей и публикация `window.*` (клиент) или сборка (сервер). Ориентир — не больше 150–250 строк.
7. README папки: обнови раздел про файлы (что в каком). Только текущее состояние, без истории.

## Проверки — после каждого выделенного файла, не в конце

- `node --check <файл>` на каждый новый файл.
- Клиент: потерянные глобалы ловит ESLint с одним правилом. Пример команды (подправь флаги, если версия ругается, но проверку не пропускай):
  `npx --yes eslint@9 --no-config-lookup --rule '{"no-undef":"error"}' --parser-options 'ecmaVersion:2022' --parser-options 'sourceType:module' --global 'window,document,fetch,console,setTimeout,clearTimeout,setInterval,clearInterval,requestAnimationFrame,cancelAnimationFrame,localStorage,sessionStorage,location,history,navigator,URL,Blob,FormData,AbortController,CustomEvent,Event,KeyboardEvent,MouseEvent,MutationObserver,ResizeObserver,IntersectionObserver,performance,getComputedStyle,htmx,EasyMDE' <файлы>`
- Циклы: `npx --yes madge --circular <файл входа>` — должно быть ноль.
- Сервер: `WATCHED_FILES` в сторожевом коде обязан видеть новые папки (`SYSTEM/cli/`) — иначе правка коннектора не перезапустит сервер.

## Ловушки

- В IIFE функции видят друг друга по hoisting; в модулях — только через `import`. Именно это ловит `no-undef`.
- `this` на верхнем уровне модуля — `undefined`; модуль всегда в strict mode.
- `try/catch`, обработка ошибок, `escapeHtml` на всём, что идёт в HTML, — переносятся дословно. Ничего не «упрощать».
- Не запускай `node server.js` — ни в фоне, ни на переднем плане: хук это заблокирует, а осиротевший процесс потом держит папку. Сервер проверяется разбором файлов (`node --check`), автоматических прогонов в проекте нет (`DOCS/decisions/025`).
